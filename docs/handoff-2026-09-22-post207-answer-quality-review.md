# Handoff — PR 207 部署后回答质量复审与防复发方案

## 结论：交付路径修了，回答质量还没有彻底解决

PR #207 已合并、重建并部署，当前 host 为 `cc71f8223138a010b70c2e211cf739fa3a7ac57c`。它解决的是聊天新请求被当作旧任务追加、回复归属混淆，以及部分发送失败被当成功的问题；不能把这些机械修复等同于“现在一定回答得好”。

本次重新读取运行数据、当前代码和开放的 INV 合同，发现一个仍存在且能复现的问题：**记忆系统在做“预算内优先装哪些”，而不是“这次问题需要哪些”。** 即使筛选返回空数组，仍回填旧记忆。Nova 留存的旧记忆又包含大量助手自己的“立场稿、盲区、1:1 核验、主轴”叙述。它们有持续进入后续上下文的通道。

这比“再加一句说人话”更接近可修的原因。但应严格区分：

- 已证明：旧叙述实际存在；当前代码会把不相关的默认记忆送入上下文；新任务仍可能继承同聊天的旧摘要；现有质量验收不足。
- 强烈怀疑：这些内容把一次研究任务的写法固化成后来所有问题的默认写法，形成自我强化。
- 尚未证明：去掉某一来源后，真实 MiniMax-M3 在原始案例上稳定恢复；没有证据把全部问题归于一次模型切换。

**因此答案不是“彻底好了，只差观察”，而是“已上线一部分修复，但回答质量还有明确的未修机制”。** 本次不擅自删除生产记忆、更换模型或发送测试聊天；下面的质量修复是待实施方案，不冒充已交付。

## 2. 原因不是一个：把三类故障分开

### 2.1 “带到了”却没回答：请求与交付的归属问题

PR #205 修了正文关键词误判和压缩工具示例复播旧叙述；PR #207 进一步取消聊天入口隐式 steering，普通输入独立排队，显式回答/追加绑定目标，按消息因果关系取回复。

它们修的是**请求不该消失、不该借用别人的答案**。现阶段仍不等于全链路保证交付：

- 通用逐件持久回执、崩溃恢复、部分成功恢复还未完整实现。
- 旧 delivery debt 仍可能在模型返回时关闭；失败附件保留后可能被后续任务再次收取。
- 重启前问题卡的内存绑定尚未恢复，旧卡会被拒绝而不是无缝继续。
- app 入口和无 messageId 的历史恢复记录不在本次完整迁移范围。

这些属于 INV-616 的 H3a 及相关 custody 工作。它们可以继续修，不应再等 OVP 第二阶段，但也不能承诺外部渠道在网络不确定时恰好一次。

### 2.2 “核了多少项、找了多少盲区”：旧输出被反复当背景

本次只读检查 Nova 的实际文件：

`~/.agentbox/agents/d08328be-7e80-4b3d-997b-be190d144643/memory.jsonl`

共 60 条。以下是定位和内容摘要，不将整段私人聊天复制进仓库：

| 行号 | 来源/时间（UTC） | 相关内容 |
|---|---|---|
| 11 | episode，09-19 06:11:47 | 把此前若干研究串成统一工程“主轴”，每条按立场稿与盲区归档 |
| 23 | episode，09-19 06:53:30 | 将“1:1 核完事实链、若干盲区、前十几条主线”写成完成记录 |
| 40 | episode，09-20 00:38:55 | 自述关闭多条线程，列出各自核验事实数量与立场稿 |
| 55–56 | extracted，09-20 00:58:33 | 记录多维度/caveat；甚至记录“没有问题、没有立场稿要求，但可能想让我核事实、写立场稿、找盲区” |
| 57 | episode，09-20 00:58:51 | 再次归纳为旧主轴与成套 caveat |

尤其第 56 条是**助手对用户意图的猜测**，不是用户明确设置的长期偏好。现在缺少足够强的来源、用途与适用范围隔离。

只读复现使用当前合并代码、这 60 条记录，给 `chooseRelevant` 注入返回 `{"selected":[]}` 的替身选择器，分别问：

- “WeVisDoc 是什么，有什么用？”
- “介绍一下图像识别”
- “明天会议几点开始？”

三次都调用选择器一次，返回相同 11 条记忆、略去 49 条，其中 7 条带上述旧研究叙述；`renderMemory` 连同索引渲染约 6291 字符。**这是确定性代码实验，不是真实模型判定三次都无关，也不是新线上回复。**

原因定位到 [memory.ts](../src/host/memory.ts)：

1. `chooseRelevant` 在记录未超预算时直接全部召回，不做本轮相关性选择。
2. `selected: []` 被协议明确解释为“没有排序偏好”，随后返回默认高分集合；不是“没有相关内容”。
3. 选择了少数条目时，`recall` 仍拿全部记录填剩余预算。
4. 选择器失败时也是同样的默认召回。
5. 被省略的记忆还有摘要索引；只过滤正文、不处理索引，仍可能泄漏旧叙述。

所以不能只改模型，让它“更聪明地返回空数组”。**当前消费者根本不支持“此次不注入任何普通记忆”这个决定。** 更准确地说，这是“容量排序”与“相关性筛选”的产品语义错位，不是解析 JSON 写错了。

空选择回退路径可追到 `e9577df`（2026-08-20），解释这一语义的注释在 `7710bb7`。它不是本次 PR 才引入的变化；最近一批研究对话产生的旧记忆，使这个长期存在的机制开始有明显后果。

### 2.3 独立排队不等于独立上下文

[turn.ts](../src/host/turn.ts) 的提示构建仍会使用记忆召回、共享记忆、会话转录、摘要与任务状态。飞书私聊以聊天身份复用会话；新建任务没有自动隔离旧研究主题。

本次还检查了 Nova 对应私聊转录：

`conversations/feishu-personal-oc_d99f329dc01493cee8b0ba5c34168eea.jsonl`

- 第 337 行已经出现 WeVisDoc 的核验数量/盲区式回复。
- 第 357 行压缩摘要仍携带旧研究主轴；其中工具示例叙述复播已被 PR #205 限制，但普通摘要正文与近轮助手正文不是同一路径。
- 第 379 行为 25 题请求，第 382 行的最终正文没有逐题完成，而转向 FDE 角色叙述。

第 337 行在第 357 行之前，**不能倒因为果，把后来的那份摘要认作前一条坏回复的唯一源头**。证据支持的是反复回灌和放大路径，不是已经找到了第一句坏话的唯一来源。

原始输入里确实有批判性研究材料，随后也有仅贴 URL 的消息。这可以解释“最初为何进入分析模式”，不能证明用户授权此后每个新话题都套用同一体例。

截至本次检查，Nova 最近的 begin 记录仍为 09-20 01:02:08 UTC、MiniMax-M3、build `6597460`；没有本次部署后的 Nova 用户轮次。因此不声称已观测到新版本自然语言质量改善或再次复发。

### 2.4 提示词并不缺“先回答”

[prompt.ts](../src/host/prompt.ts) 已有：直接回答、覆盖整个问题、旧任务仅为背景、不要把转交当交付、使用清楚的语言、工具只为补必要信息等要求。记忆渲染也已有“描述而非指令”的声明。

这些软规则不足以抵消反复注入的旧叙述。继续叠加“说人话”“必须完成”，既不能阻止召回，也不能证明效果。

部署中的 box 没有 `research-reply` skill；不能把尚未安装的未来 skill 当成此次故障原因。其他研究/写作 skill 的存在也不证明这次被调用。当前没有足够证据锁定某个模型切换或某个 skill 更新为唯一原因。

## 4. 彻底解决方案：改输入和验收，不是再润色一次输出

### 第一段：先堵住旧习惯持续进入本轮的问题

落点：INV-142，记忆召回与上下文组装；涉及含义变化，按 docs/13 先审再实现。

- 明确拆分“已确认的长期用户偏好”和“普通事实/任务经验”。前者有小而独立的预算、来源和作用域；不能把二者统统清空。
- 普通记忆的 `selected: []` 应表示此次不注入；选中子集严格生效，不自动塞满剩余容量。未超预算也不能等同全部相关。
- 选择器失败有单独状态，只采用有明确依据的保守召回；不要伪装成一次相关性成功选择。
- 正文、略去项索引、共享记忆必须执行同一作用域规则。不能正文过滤了，索引把旧主轴带回来。
- 记录来源至少区分用户明确偏好、外部事实、助手推断、任务总结；绑定来源消息/任务和适用范围。助手自己的“我做了五维交叉比较”不升级为用户长期格式要求。
- 审查现有污染的派生记忆、摘要及共享投影，标记不适用/失效，保留原始转录和可回退版本。不直接删整个 memory.jsonl。
- 新任务构建当前问题需要的上下文；同聊天的已结束主题按需检索，而不是默认继续整套研究主轴。显式追问、跨轮约束与任务引用必须保留。

不能只改一行空数组分支：现有选择器提示、单测、预算语义、索引与失败回退要一起迁移，否则只是把隐式行为挪到另一处。

### 第二段：让“完成”对准用户这次要的东西

落点：INV-101、615；交付回执仍归 INV-616，不混为一个评分。

- 用户问“有什么用”，先解释用途与适用条件；问 25 道题，逐题回答或明确哪题缺什么信息；要求详细 review，允许详细，不强行缩成三句话。
- 内部核验与对外说明分离。读取状态、证据表和工具日志用于判断，不默认变成回复开头。
- 补充调查必须能说明会改变哪一项结论。无关盲区不继续扩写；证据不足时给可支持的结论和重要限制，不无限开支线。
- 区分“网页读全了”“这一断言有证据”“答案满足用户问题”“答案送到了”四件事。任何一个不能替其他三个作证。
- 25 题覆盖检查是必要条件，不是充分条件；敷衍填满 25 个编号也不算好答案。需要内容准确性和可理解性评估。
- 不用全局禁英文、禁专业词或长度上限冒充说人话；技术读者和入门读者要求不同。

### 第三段：用真实案例挡住下一次回归

当前 [scenario-live.mjs](../scripts/scenario-live.mjs) 的部分“answered”条件主要判断 `said.length > 0`；脚本模型测试能证明调度机械行为，不能证明真实模型解释得清楚。此次 release 分数卡也明确跳过模型部分。

需要一组可重复的对照：

1. 固定模型、provider、代码、提示版本、输入与记忆快照；不把成本优化或新模型混进首次实验。
2. 对照 A：当前版本；B：只改记忆；C：只隔离旧主题上下文；D：两者都改。观察到底哪个来源改变回答。
3. 使用原 25 题、WeVisDoc 入门介绍、带限制的技术比较、明确要求详细 review，以及无关新话题；每例多次运行，并覆盖历史有/无旧研究叙述。
4. 评分同时检查当前问题完成度、证据支持、通俗解释与重要限制；保留盲评样本和失败答案，不只输出一个“通过”。
5. 涉及 memory、compaction、prompt 结构、共享模板、模型切换、判断模型的新 PR 必须带同版本质量对照；缺失是未验证，不是绿灯。
6. 清洁上下文下仍失败，再做模型/provider 对照并准备回滚。现阶段没有证据支持先换 MiniMax-M3 就能根治。

真实评估应在隔离的数据目录和非投递场景运行，不能污染生产记忆，也不应自动把实验结果发到用户聊天。

## 5. 影响面与不采用的捷径

影响面包括 memory 的选择协议、renderMemory 索引、共享记忆、摘要/压缩、turn 上下文组装、长期偏好迁移、research-reply 契约、质量分数卡与 release 门禁。原始转录应保留；派生数据支持重建和撤销，旧代码回滚时须识别格式版本。INV-616 的回执状态迁移单独设计。

不采用：

- **继续堆提示词**：已有相同要求，不能阻止不相关输入。
- **删光记忆/每条消息开新会话**：会丢用户偏好与真正追问；还没隔离原因。
- **只换 Jev 或大模型**：消费者语义不变时同样会塞回旧内容；也无法证明唯一原因。
- **最后统一“人话改写”**：能改善措辞，却可能把跑题内容包装得更流畅；不能补回没回答的 25 题。
- **任何资料未读全就拒绝答复**：完整度不是证据充分性的替身，会制造永久核验支线。
- **只加禁词测试**：删掉“盲区”二字并不消除答非所问，合理的审查也不该被禁止。

## 6. 怎么把方案弄坏：必须加入的验收输入

| 输入/故障 | 必须得到的结果 |
|---|---|
| 60 条旧研究记忆，普通记忆选择为空，问新领域入门问题 | 不回填旧主轴；长期偏好仅按独立已确认规则保留 |
| 只选中 1 条，剩余预算很大 | 不顺手加入其他 59 条，也不从索引泄漏 |
| 只有 2 条、不超预算，但都与问题无关 | 仍允许零召回 |
| 选择器超时/无效 JSON | 明确失败策略；请求仍可回答，不默认吞入整批旧叙述 |
| 过滤 memory 后，旧摘要和共享模板仍写“每次列五个盲区” | 不能经另一入口恢复；记录触发来源便于追查 |
| 同聊天先深入审查，再问“它有什么用” | 新回答对准用途；需要旧事实时可引用，不继承审查体例 |
| 明确追问“继续上面第 4 点” | 正确保留指代；不能为了隔离主题丢掉必要上下文 |
| 25 题中 1 题缺证据 | 其余 24 题给答案，单独交代未知题；不能只确认接手 |
| clipped 页面已有相关段落；full 页面含未经支持的宣传 | 前者可作有限支持，后者不因 full 自动变真 |
| 用户要求详细 review、专业英文名词合理 | 允许必要细节与术语解释，不套简短风格评分 |
| 压缩/重启前后、旧派生格式迁移失败 | 来源与作用域不丢；不会恢复已失效的写作偏好 |
| 文本送达、附件失败；或超时结果未知 | 分别记录，未知不当成功也不盲目重发，归属原请求 |

验收完成应同时具备：确定性用例、真实模型对照、人工抽查、部署后的隔离冒烟与可回滚记录。只能承诺在明确范围内有证据阻止已知回归，不能承诺所有自然语言任务永远不再答坏。
