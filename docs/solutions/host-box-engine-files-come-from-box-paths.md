# On a host box, a delegated engine's files cannot be at the image's /home/box paths

**Symptom.** On a native-environment box (`kind: "host"`), `Delegate` fails before the engine starts. The box refuses to write the MCP face file or the relay config (`/home/box/... is outside the directories this box may touch`). Or the engine starts but cannot find its provider config, its skills or its report path. The work volume, the engine homes and the install prefix were all hard-coded to the Docker image's layout.

**Cause.** The presets and the Delegate tool named `/home/box/work/...` and `~/.claude`, `~/.config/opencode`, `~/.pi/agent`, `~/.agents` directly. On someone's own machine `/home/box` does not exist, and `~` belongs to that person: the sandbox refuses writes there (INV-1700) and hides their engine logins (INV-1710).

**Fix.** Every path a delegation names comes from `boxPaths({ kind, workDir }, agentId)` in `src/host/box-paths.ts`. Never test the box kind in a preset or a tool. A Docker or attached box gets `DOCKER_BOX_PATHS`, which are exactly the old paths (`box-paths.test.ts` checks them byte for byte). A host box gets its work directory from the registry entry. Each engine home sits under `<work>/.state/<agent>`, at the subdirectory `STATE_VARIABLES` gives (one table: boxd's `stateEnvironment` points the engines there, and the host derives the file paths from the same table). The skills links are made before each run (`delegateCommand`), not at install, because the install belongs to no single agent. pi is pointed with `PI_CODING_AGENT_DIR` (measured on 0.85.1). mcode reads `~/.agents/skills` and has no variable to move it, so on a host box it gets no skills mount there; it also reads `<data dir>/skills` (its "user-global" root, read from 0.6.12), and its run already makes a data directory of its own, so on a host box the run links the box's skills into it (`mcodeProfileShell`). The report path is recorded with the delegation (`data.report`), so settling reads the file the brief named. The host's own skill readers and writers follow the same rule: the box's skills directory is `skillsDir(box)` (`<work>/skills` on a host box, `/home/box/work/skills` on the image), never `SKILLS_DIR`, or the starters are seeded where the box refuses them and the engines' links point at an empty directory (INV-1719). Watch for these:
- On a Docker box the engines' `bin` is **appended** to PATH (the image's layer is found first). On a host box that would let an engine the person installed themselves (Homebrew, `~/.local/bin`) win, so there the pinned engine is never looked up (INV-1720). `boxPaths(...).pinnedEngine(program)` gives its absolute path in the install directory. `probeCommand` checks that file and the version its install's `package.json` names, not `command -v`. `delegateCommand` puts the install's `bin` first, refuses with exit 127 if the file is gone, and defines the engine's name as a shell function that calls the absolute path, so a profile function cannot take its place either. A missing or stale pinned engine is reported by `engineMissing` and offered for install. It is never replaced by the person's own engine. A test that starts a fake engine should put a fake "person's own" engine first on PATH and assert it did not run (`box-paths.test.ts` does).
- A host work directory is spliced into shell lines unquoted, so `boxPaths` refuses one that would need quoting and says to restart with `agentbox host up --work`.

**Verify.** `node --experimental-transform-types --test src/host/box-paths.test.ts`, run outside a sandboxed test runner so the real sandbox is available. Under that sandbox, fake claude, opencode, pi and mcode binaries are started the way Delegate starts them, with a fake engine of the person's own first on PATH that must not run. Each reads its MCP face, its relay config and a skill linked from `<work>/skills`, and so does a fake mcode through `$MINIMAX_DATA_DIR/skills`; the starters are first seeded through the box's file routes and its confined shell, and every engine finds one. Claude's state lands in `<work>/.state/a1/claude`, and the fake home stays empty. `src/host/mcp-face.test.ts` runs the Delegate tool against a host box and checks that the face file and the skills link are under the work directory.
