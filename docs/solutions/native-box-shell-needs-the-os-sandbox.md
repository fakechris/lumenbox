# On a host box, a path check on the file routes does not confine the shell

**Symptom.** A native-environment box (`kind: "host"`, `agentbox host up`) refuses `write_file` outside its granted directories, yet `bash` writes to `~/.zshrc`, reads `~/.ssh`, or runs `rm -rf` on a directory nobody granted. The writes are logged as "writes on the person's own machine" and nothing stops them.

**Cause.** `headless.ts` checks paths only for the file routes. `POST /exec`, background jobs and delegated engines (`/acp/open`) all spawn `bash` as the daemon's user. Inside a container that is acceptable because Docker is the wall. On someone's own machine there is no wall. The host-side "review" of those writes was an auto-review verdict in `shadow` mode, which records and never blocks.

**Fix.** Every process boxd starts for an agent on a headless box goes through `confinementFor()` (`src/boxd/confinement.ts`), which wraps it in the `RunOnHost` sandbox (`src/host/host-sandbox.ts`). The sandbox is `sandbox-exec` on macOS and `bwrap` on Linux. Writes are allowed only in rw roots, the work directory, `$TMPDIR` and `/tmp`. ro roots stay read-only even under an rw root. Credential places cannot be read. The only network is the egress proxy. When the sandbox is unavailable, the wrap throws `ConfinementRefused` (HTTP 403) and nothing runs: never fall back to bare. On the host, the policy gate asks before any write on a host box (`hostBoxWrite`, `onHostBox` set by dispatch). Read-only commands do not ask (`shell-readonly.ts`). An operator `allow` rule with `tool:`/`command:`/`path:` lifts the ask. Watch for these:
- Pass the start directory as `runIn`, never as `cwd`. `cwd` becomes writable, so a request with `cwd: ~` would open the whole home directory.
- Seatbelt matches real paths, so resolve everything first. On macOS `/tmp` is `/private/tmp`, and the session wrapper writes `/tmp/boxd-session-*`.
- `bwrap --ro-bind` fails on a path that does not exist. The deny and read-only lists keep only existing paths.
- Under the sandbox, tools and delegated engines that write state under `$HOME` (`~/.npm`, `~/.cache`, `~/.claude`, `~/.codex`) are refused, which made engines unusable on a host box. Do not widen the sandbox to the real home: that hands the box the person's own engine logins. Each agent gets a state directory, `<work>/.state/<agent>` (INV-1710). `confine.wrap()` returns `env` that points `XDG_CACHE_HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME`, `npm_config_cache`, `CLAUDE_CONFIG_DIR` and `CODEX_HOME` into it. Exec, jobs and `/acp/open` merge that env **last**, over the request's env, because the presets name `/home/box/...` homes that do not exist on a host box. `/acp/open` carries `actor: agent:<id>` so an engine's `session/load` after a restart finds the same directory. The person's engine homes (`ENGINE_HOMES_UNDER_HOME` in `host-sandbox.ts`: `~/.claude`, `~/.claude.json`, `~/.codex`, `~/.gemini`, opencode's, `~/.pi`) are hidden and write-denied, like `~/.ssh`. As a result, an engine on a host box has to be logged in from the env the host passes (relay token), or inside its state directory. It never borrows the person's login. The per-agent split is for order, not secrecy: all agents on one box run as one user.
- Known gap: on macOS, Claude Code keeps its login in the login Keychain rather than in `~/.claude`. The Seatbelt profile is `(allow default)` and denies no Keychain service, so hiding the files is not evidence that a confined `security find-generic-password` cannot read that login. This is unverified and open.

**Verify.** `node --experimental-transform-types --test src/boxd/confinement.test.ts`. Its last test runs real commands under the real sandbox where one is available, and is skipped where it is not, including under a sandboxed test runner. It checks that a write outside the roots fails and leaves no file, that a ro root is not writable, that `~/.ssh` cannot be read or written, that `rm -rf` outside the roots removes nothing, that a write to `$XDG_CACHE_HOME` lands in `<work>/.state/a1/cache` while `~/.cache` stays shut, that the fake `~/.claude` and `~/.codex` logins can be neither read nor written, that `npm config get cache` names the state directory, and that a job finds `$CODEX_HOME` in the state directory even when the inherited environment named `~/.codex`. The test sets `HOME` to its fake home, so it never reads the real one. `boxd` started headless logs `commands run under sandbox-exec: …` at start-up. With the sandbox missing, it logs `every command is refused`.
