# A node's own Mac screen: read the permissions, never ask for them, and keep the shell off the screen

**Symptom.** Three things go wrong when an organisation node opens its Mac's own screen to the `computer` tool (`agentbox node run --screen`, `AGENTBOX_NODE_SCREEN=1` for the app). A dialog ("LumenBox would like to record this computer's screen") appears on a machine nobody is sitting at, and the batch hangs behind it. A capture comes back as only the wallpaper and the menu bar, and the model acts on it. A confined `bash` runs `screencapture` or `osascript` and reaches the screen without the takeover lease, the owner check or the approval card.

**Cause.** Screen Recording and Accessibility are TCC permissions held by the *responsible* app: LumenBox when the app starts the node, Terminal when someone runs it by hand. Every process that app starts inherits them, including the daemon's confined shell. `screencapture` without the permission prompts, or on newer macOS captures only the desktop picture without failing. Events posted without Accessibility are silently dropped.

**Fix.** The driver is `src/cua/macos-executor.ts`. The DisplayManager runs it as desktop 1 through `src/boxd/native-screen.ts`.
- Every batch starts with the helper's `state`: `CGPreflightScreenCaptureAccess()` and `AXIsProcessTrusted()`. Both only read and never prompt. A missing permission is `PERMISSION_DENIED` before any capture or input (`not_delivered`). `screencapture` runs only after the read said yes. Never call `CGRequestScreenCaptureAccess`, `AXIsProcessTrustedWithOptions` with the prompt option, or System Events (Automation prompts too). `macos-executor.test.ts` fails if the helper source names any of them.
- After a batch that wrote, `state` is read again. A permission withdrawn mid-batch is reported as an error after dispatch, which reads as unknown, never as done.
- CoreGraphics posts in points and `screencapture` captures pixels (twice as many on Retina). The scaler maps API space to the main display's bounds in points, `sips --resampleWidth` brings the capture to API width, and the result is a PNG (`screenshot_media_type: "image/png"`, which the host passes to the model as such).
- Where the screen is open, the confined shell's Seatbelt profile refuses to exec `SCREEN_PROGRAMS` (`screencapture`, `osascript`, `osacompile`, `automator`, `shortcuts`). The host's shell guard also refuses `screencapture`, alongside `osascript` and `cliclick`. **Gap, not measured:** a compiled program the agent builds itself could still call `CGEventPost` or `CGDisplayCreateImage`, because the profile denies no WindowServer Mach lookup. Measure that on a throwaway user session before denying `com.apple.windowserver.active`. Never measure it on a person's real session.
- The default helper is JXA run by `/usr/bin/osascript`, with the request on stdin. A node can name a signed helper that speaks the same requests with `BOXD_NATIVE_SCREEN_HELPER`. Typing goes through `CGEventKeyboardSetUnicodeString`, one character at a time, so that text with no key on the layout, such as Chinese, is typed as text. That JXA bridging has not yet run on a real Mac: the check by hand below is its first test.

**Verify.** `node --experimental-transform-types --test src/cua/macos-executor.test.ts src/boxd/native-screen.test.ts` uses fake hands: points scaling, the PNG at API width, refusal before dispatch for each missing permission, a mid-batch withdrawal, takeover and stop stopping the batch at the next input, one agent at a time, and the screen never reaped. Nothing in `npm test` touches a real screen. On a real node, by hand: with neither permission granted, a `computer` screenshot answers PERMISSION_DENIED naming Screen Recording, and **no dialog appears**. After granting both and restarting the node, a click lands where the screenshot shows it, `type` puts `订单 42` into a text field, and `cmd+s` saves. Take over from Settings and the agent's next input is refused USER_IN_CONTROL. Withdraw Accessibility in System Settings and the next batch is refused. Stop the node and nothing more moves. In the box's shell, `screencapture /tmp/x.png` prints "Operation not permitted".
