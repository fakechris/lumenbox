# Handoff — 上下文恢复第六项：通用无副作用 /retry

## 交付结果

普通问答即使没有任务号，也能在独立私聊发送 `/retry`。host 会从当前 epoch 找到最近一次
已回答的本人请求，用 turn 的 `causedBy` id 回到不可变消息账本，建立新的 recover epoch，
只按原文重新回答。旧答案、旧聊天、摘要、长期/共享记忆、skills、计划和任务不会进入。

## 安全边界

- 第一版零工具、零自动学习，不会因“再答一次”重复发送、发布、删除或部署。
- 群聊、main/fork、忙会话、缺少消息 id、跨身份/会话来源、摘要来源和带附件的原请求均
  在修改 epoch 前拒绝。
- 重复投递同一个命令只返回原切换结果；它不会再建立一个 epoch。
- Web 增加 👎。它只提示 `/retry`，不会由模型自评、语气或模糊关键词自动清空上下文。

## 验证

单元测试覆盖来源回溯、多个消息保序、幂等和拒绝边界；channel 测试证明 retry 不新建任务；
整栈场景复现“只说已转交、继续五维核验”的污染回答，并证明重答只看原始问题且没有工具。
