# LumenBox 0.4.7: fixes from the first week of 0.4.6

A fix release. Nothing new to learn; several things that went wrong now don't.

## Fixes

**Reminders and members**
- A reminder meant for a chat is no longer lost when its turn cannot start and the member cannot take the note either. It stays owed and reaches the member as soon as it can; Settings → Automations says so.
- A member whose tools leave out reading back old output now keeps that output in full after a long idle pause, instead of having it replaced by a pointer it cannot follow.
- Messaging a colleague from inside a task no longer fails the colleague's turn.
- What the app itself tells a member is framed as coming from the app, not from a teammate, and a retry after an approval says plainly what happened.
- A finished side job that never stated its outcome is no longer listed as unfinished.

**Safety**
- A connector tool reached through the tool lookup is checked by the approval rules under its own name, the same as when it is called directly.

**Running boxes on servers and Kubernetes**
- Docker host builds carry their version and commit, so a box reports what it actually runs.
- The tenant UI is served over the cluster's internal HTTP.
- A reallocated box keeps the storage settings of the volume it adopted.
- The Kubernetes smoke test and prewarm read kind's standard kubeconfig.
- The Kubernetes deployment guide is corrected in four places.

## Upgrading

Nothing to do. Data from 0.4.6 loads unchanged.

## macOS downloads

- Apple Silicon: `LumenBox-0.4.7-arm64.dmg` or `LumenBox-0.4.7-arm64-mac.zip`
- Intel: `LumenBox-0.4.7.dmg` or `LumenBox-0.4.7-mac.zip`

These builds are **not Apple notarized**, so macOS may block the first opening. Either right-click LumenBox and choose *Open*, or run `xattr -dr com.apple.quarantine /Applications/LumenBox.app`.

`SHA256SUMS` identifies the exact published files.

## Box image

`fakechris/lumenbox:0.4.7` — linux/amd64 and linux/arm64. Once the app is running, it offers *Apply update* for the box.
