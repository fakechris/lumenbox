# LumenBox 0.4.13: you land on your own sandbox and agent, in one vocabulary

On an organisation whose sandboxes run on Kubernetes, the first screen no longer offers a shared box that cannot start. Every person, the first Admin included, opens on their own sandbox with their own agent under it, and the getting-started list shows only steps that can be done from where they stand.

## What changed

**The first screen**
- On Kubernetes, the installation's own sandbox is not shown and no starter team (Ada, Ops, Rex, Vera) is made in it. A direct message or `@Name` does not reach agents that cannot run.
- The sidebar has one heading per sandbox you may use, "Your sandbox · Ready" for yours, with its agents under it. A sandbox that failed says why in plain words and offers one button that works.
- Getting started is one list in both editions, worked out from your own state: model, your sandbox, your agent, a chat channel (Admin). A step you cannot do here is not shown.
- Settings → Organisation (Admin, organisation only) gathers the channel app, the public address and member activation.
- An installation 0.4.10–0.4.12 already opened keeps the four starter agents' records. Settings → Sandboxes lists them under "Agents that cannot run here", with a button that deletes them and archives their records.

**One vocabulary**
- Every page, the manual and the server's messages say **sandbox / 沙盒** for the computer an agent works on and **智能体** for an agent in Chinese. 成员 means a person only. The words checker refuses the old ones.

**Client API `/api/v1` (preview for the mobile apps)**
- Personal and service tokens (minted at `/api/client-tokens`), `GET /api/v1/meta`, `/me`, `/agents`, `/work`, `/work/{id}/history`, `/board`, `/events`, and `/changes?since=`. `/changes` comes from a change record kept on disk, so a client catches up after days offline or a server restart.
- The OpenAPI document is `docs/api/v1.openapi.json`. A field, value or operation in it is never removed within v1.

**Also since 0.4.12**
- A rotated box token reaches the Kubernetes Secret. A control-plane account holder can rotate a tenant sandbox's tokens. The Outbox records who answered an approval.
- A task that asks for a file gets it.
- A mac build that is not Developer ID signed can no longer pass the release check.

## Upgrading

Data from 0.4.12 loads unchanged. On Kubernetes (`organisation.yaml` or `control-plane.yaml`), update the Deployment container `image` and `AGENTBOX_IMAGE` to `fakechris/lumenbox:0.4.13`.

## macOS downloads

- Apple Silicon: `LumenBox-0.4.13-arm64.dmg` or `LumenBox-0.4.13-arm64-mac.zip`
- Intel: `LumenBox-0.4.13.dmg` or `LumenBox-0.4.13-mac.zip`

These builds are signed with a Developer ID but **not Apple notarized**, so macOS may block the first opening. Either right-click LumenBox and choose *Open*, or run `xattr -dr com.apple.quarantine /Applications/LumenBox.app`.

`SHA256SUMS` identifies the exact published files.

## Box image

`fakechris/lumenbox:0.4.13` — linux/amd64 and linux/arm64. Once the app is running, it offers *Apply update* for the box.
