# LumenBox 0.3.15: one agent can't fill the box

## What is new

**Each agent's background work has limits inside the box.** Before, one agent could start
dozens of scans at once, and the box's memory ceiling only decided which processes the system
killed, often another agent's. Now:
- An agent runs at most 4 background jobs at once. Past that, a new one is refused, and the
  agent is told what it is running and how to free a slot. A command that runs past its
  foreground time while the agent is at its limit is stopped, with the same explanation.
- One job's processes may hold at most 1 GB of memory. A job past that is stopped, and its log
  says why. Other agents' work is not touched.
- Searches with ripgrep use 2 threads unless asked for more.

**The box keeps a bounded amount of its own output.**
- One job's log is at most 64 MB. Past that, its beginning and its last 2 MB are kept, with a
  line saying how much was cut.
- Finished jobs' logs are removed after 7 days, or oldest first once they pass 1 GB together.
  The overflow output of long commands is capped at 512 MB. Running jobs are never touched.
- Workspace searches skip the box's own job logs and overflow output, so a scan's output no
  longer feeds the next scan. Naming those folders still searches them.
- The box's self-check reports when the logs were last pruned.

**Updating the box is reliable when Docker is slow.** If starting the new box hangs or fails,
LumenBox now checks what Docker actually left behind. A box that came up counts as updated. A
half-made one is removed, so going back to the previous image works. Before, a slow Docker
engine could report "update failed, going back failed too" while leaving the box down.

**Settings → Boxes → Resources** shows what LumenBox and the box are using right now: the app's
memory, event-loop delay, each agent's turns, queued messages and watched jobs, and the box's
memory, out-of-memory kills and CPU. An admin can save a memory snapshot for diagnosis. It may
contain conversation content, so delete it afterwards.

**Fixes**

- The box's access token no longer appears in the update's progress, in `server.log`, or in
  the process list when the box is created.

## Install on macOS

Download the disk image for your Mac, open it, and drag LumenBox to Applications.

- `LumenBox-0.3.15-arm64.dmg`: Apple Silicon
- `LumenBox-0.3.15.dmg`: Intel

The apps are signed but **not notarized**. The first time, right-click LumenBox and choose
*Open*, or run `xattr -dr com.apple.quarantine /Applications/LumenBox.app`.

## The box image

`fakechris/lumenbox:0.3.15` (linux/arm64), with the same engines as 0.3.14: opencode 1.18.25,
Claude Code 2.1.250, pi 0.85.1 and mcode 0.6.12. The limits above live in the box, so they take
effect after you open Settings → Boxes and choose **Apply update**.
