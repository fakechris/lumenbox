# LumenBox 0.3.10: supervision

## What is new

**Supervision runs with the app.** LumenBox now runs a small supervision process next to its
server. You install nothing extra: it starts and stops with the app, and the tray shows whether
it is running.

- **Watchdog, on by default.** It tells you when work in hand has stopped moving, when a goal the
  system stopped has nobody looking at it, when a goal keeps failing its check, or when LumenBox
  itself stops answering. Its flags land on your "needs you" list and in the task's chat. A flag
  never changes the work.
- **Supervisor, optional.** Give it a goal and it starts it for you, then watches it to the end.
  Its model is your choice: any provider you have set up in Settings → Model, with OpenAI's
  gpt-6.1-sol recommended. It can start the goal, read its record, pause a goal it started, and
  ask you to look. It cannot touch the box, mark work done, resume what the system stopped, or
  raise a budget.
- **Settings → Supervision** holds both. The first time you open it, a five-step guide takes you
  from "what is this" to a first supervised goal. It tests the model before you rely on it,
  shows the most a run can cost, and asks you to confirm before it creates anything on your
  board.

**A door for other agents.** Another agent or tool can work with your team through the MCP door
in Settings → MCP:

- Start a goal and control it: pause, clear, or resume a pause it made itself.
- Read a task's record as structured data.
- Wait for changes instead of polling.

Every action that changes something can be retried safely.

**Fixes**

- Side-door tokens now survive a restart. Before, every app restart signed out every connected
  tool.
- A goal that continued after a pause could stop the LumenBox server. It no longer does.
- Operator rules written for one person now apply to that person. Before, they never matched.
- Chromium pages in the box have a readable control tree again, so agents can work a web page by
  its buttons and fields instead of guessing pixels.
- Desktop actions say more precisely whether they landed. A control that moved or appears twice
  is refused rather than clicked by mistake.

**Also**

- Writing to Feishu and DingTalk docs checks before it writes and reads back after.
- A goal remembers which ideas it already tried and stops when it starts repeating itself.
- A box that was rebuilt ignores slow callbacks meant for its previous self.
- Memory is chosen more carefully for each turn.
- Git in the box can use a stored credential without the agent seeing it.

## Install on macOS

Download the disk image for your Mac, open it, and drag LumenBox to Applications.

- `LumenBox-0.3.10-arm64.dmg`: Apple Silicon
- `LumenBox-0.3.10.dmg`: Intel

The apps are signed but **not notarized**. The first time, right-click LumenBox and choose
*Open*, or run `xattr -dr com.apple.quarantine /Applications/LumenBox.app`.

## The box image

`fakechris/lumenbox:0.3.10` (linux/arm64) carries opencode 1.18.25, Claude Code 2.1.250, pi
0.85.1 and mcode 0.6.12. To load it into an existing box, recreate the box with
`agentbox box up --recreate`, which backs up its volumes first.
