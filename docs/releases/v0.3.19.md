# LumenBox 0.3.19: a plan that runs out, a job that ends, a claim checked twice

This release is about what happened on 4 November, when five agents ran overnight until the
model plan was used up: 1,575 wakes, 1,377 of them "a command you started has ended".

## What is new

**A finished command wakes an agent only when it has something to say.** A command that runs
past its foreground window keeps running as a job, as before. By default, the agent is now woken
only if the job fails (a non-zero exit, a kill, or a line it asked to watch for). A job that
succeeds is noted at the start of the agent's next turn. Jobs that end within 20 seconds of each
other share one wake. A command that only waits (`sleep`, `tail -f`) never wakes anyone, and the
agent is pointed to `Jobs wait`, which costs nothing while it waits. Replayed over 4 November's
records, these rules cut job wakes from 1,377 to 152.

**Each agent has a spend line for the day and for a single wake.** The defaults are 20 per day
and 2 per wake, in the same unit as `AGENTBOX_RATES`. At 80% the agent is warned. At the
per-wake line, the turn ends and hands back what it has done. At the daily line, the agent is
paused, admins are told, and it resumes the next day unless you resume it sooner. Models
without a configured price are held to a token count instead and named. You can see and change
each agent's lines in Settings → Team → Agents. Paused agents appear under "Needs you".

**A claim is checked by two reviewers, not by everyone.** When a task goes to review, it is
sent to K reviewers (default 2, `reviewersPerClaim` in config). Each verdict is recorded against
the claim and its evidence. Other agents who look at the task see that record instead of
checking again. New evidence starts a new round.

**A plan that runs out stops being retried.** A "usage limit" or "insufficient quota" answer
from a provider now rests that account for every agent: for 15 minutes, then an hour, then four
hours. It is not retried in a loop and not mistaken for a busy server. A plain rate limit is
still a short retry. Settings → Model Provider shows the rest and has **Retry now**. Optionally,
`AGENTBOX_QUOTA_PAUSE_AT` stops new calls before a rolling 5-hour forecast reaches your line.

**Fallback providers.** `fallbackProviders` in config (up to three) lists providers to continue
with while the main one rests.

**Effort follows the kind of call.** Turns and delegates ask for medium effort, and summaries
and housekeeping for low, where the provider supports it. Claude turns stay at high.

**Memory is found by meaning, too.** Recall now finds a memory by what it is about, not only by
its exact words.

**Team memory can wait for a person.** With `teamMemoryReview` on, what agents share as team
memory waits for your approval.

**Who is speaking.** The model is given one table that says who wrote each part of what it
reads: you, a teammate, or the host.

## Install on macOS

Download the disk image for your Mac, open it, and drag LumenBox to Applications.

- `LumenBox-0.3.19-arm64.dmg`: Apple Silicon
- `LumenBox-0.3.19.dmg`: Intel

The apps are signed but **not notarized**. The first time, right-click LumenBox and choose
*Open*, or run `xattr -dr com.apple.quarantine /Applications/LumenBox.app`.

## The box image

`fakechris/lumenbox:0.3.19` (linux/arm64), with the same engines as 0.3.18: opencode 1.18.25,
Claude Code 2.1.250, pi 0.85.1 and mcode 0.6.12. Nothing in the box changed in this release;
everything above runs in the app.
