# LumenBox 0.3.12: the box cannot act as you on this machine

## What changed

**Security fix — please update.** An agent in the box could reach this machine's LumenBox page
and, with a credential it found in the box's browser, act as any person on your team, admin
included. On the installation where this was found, agents used it to read and change tasks and
to read other agents' transcripts while working on their own audit tasks. No setting or key was
changed. docs/10 (S-4) has the full account.

- The box's names for this machine (`host.docker.internal` and the like) serve only the agents'
  own tool door. The LumenBox page and its API refuse them, so the box's browser can no longer
  sign in here.
- Identity headers are believed only when a hosted gateway stands in front. A desktop ignores
  them.
- This machine's UI token is replaced by its name in what agents are shown: tool results,
  resumed results, and the activity stream.

**After installing, rotate your UI token** if your box's browser ever opened the LumenBox page:
quit LumenBox, delete `~/.agentbox/ui-token`, and start it again. A new token is made, and open
tabs sign in again.

## Install on macOS

Download the disk image for your Mac, open it, and drag LumenBox to Applications.

- `LumenBox-0.3.12-arm64.dmg`: Apple Silicon
- `LumenBox-0.3.12.dmg`: Intel

The apps are signed but **not notarized**. The first time, right-click LumenBox and choose
*Open*, or run `xattr -dr com.apple.quarantine /Applications/LumenBox.app`.
