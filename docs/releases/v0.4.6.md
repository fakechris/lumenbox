# LumenBox 0.4.6: members tell you less noise and more of what matters

## What is new

**What waits on you is one light card above the conversation.**
When a member needs you, it writes the card itself: an action as the title, a short paragraph saying what happened and what to do, and a separate line for what it has not checked. The buttons follow what is actually in the way: *I've done it / Skip for now* when you have to do something elsewhere, the two outcomes the member named when it needs a go-ahead, *Confirm / Send back* for a delivery. Several requests from one member sit in one place with *1 of 3* paging. A reply attaches to the card on show. A settled card shrinks to one line saying what was decided. Sending work back with a reason now actually wakes the member.

**A delivery is written in one fixed order.** One sentence of result, the main change and the one place worth your closer look, what was verified and how, then what was not done or not verified, which is never folded away.

**A member's row says what it is doing, in its own words.** The member list shows the card it owes you, else the step it is on, else a plain status. A line from an hour ago does not pretend to be current.

**Members speak up less at the wrong moment.**
- A member can tell you one thing in the middle of a long job and keep working (with files as real attachments in Feishu, DingTalk and Telegram).
- A message nobody asked for waits until the conversation has been quiet for three minutes, at most thirty.
- Routines pause after a week in which nobody wrote to the box, say so once, and resume when you write again. A routine can opt out.
- A member can set itself a one-off reminder; Settings → Automations lists them and lets you dismiss one.

**Safer by default.**
- Writing a file that something will run later — a git hook, `.mcp.json`, a CI workflow, `package.json` scripts, a shell startup file, a cron or launchd unit — asks you first, in any box.
- When a node opens its own Mac screen to members, a program a member compiles itself can no longer capture the screen or send input around the approval gate.
- A box started with an egress relay is now confined to it at the network layer. Without a relay nothing changes, and the start-up log says the box is not confined.
- What the app itself sends a member (setup cues, audits, retries) is no longer recorded or remembered as something you said.

**Memory and history.**
- Memory keeps a fact only if it can quote where you said it; correcting a fact replaces it instead of keeping both, and repeating a preference keeps it fresh.
- One search over every conversation of every member: members can use it, and the system page has a search box. The index is built on first use, under your LumenBox data folder.
- After a long idle pause, old tool output is left out of the next request (it can be read back), which makes the first request after a break much smaller.

**Recordings and checks.**
- Members can produce a verification report with a screen recording, step by step, shown as one card.
- Screen recordings expire after 14 days or above 2 GB per box, stay out of box backups, and are only readable through the member's own box.
- Settings → Supervision has a calibration page where you can label the app's own reviewers; until you do, they behave exactly as before.

**Fixes.** Sending with no model configured says so instead of leaving a stuck job. A new routine shows in the list right away and says it starts paused. An automation that a non-default member cannot run is refused when you save it. The welcome page's box status follows a start or stop from the command line. The first admin on a fresh command-line web install is guided through issuing an MCP token.

## Upgrading

- New files appear in your LumenBox data folder as features are used: a queue of waiting messages, the conversation search index (roughly two thirds of the size of your conversation history), your reviewer labels.
- Memory written by earlier versions loads unchanged.
- Expect a few more *asks* the first days: writing a run-later file now always asks.
- Routines in a box nobody has written to for a week pause on their next run. Write in that box, or set `when_idle: run` on the routine, to keep it going.

## macOS downloads

- Apple Silicon: `LumenBox-0.4.6-arm64.dmg` or `LumenBox-0.4.6-arm64-mac.zip`
- Intel: `LumenBox-0.4.6.dmg` or `LumenBox-0.4.6-mac.zip`

These builds are **not Apple notarized**, so macOS may block the first opening. Either right-click LumenBox and choose *Open*, or run `xattr -dr com.apple.quarantine /Applications/LumenBox.app`.

`SHA256SUMS` identifies the exact published files.

## Box image

`fakechris/lumenbox:0.4.6` — linux/amd64 and linux/arm64. This is the first release whose box image runs on Intel and AMD Linux hosts. Once the app is running, it offers *Apply update* for the box.
