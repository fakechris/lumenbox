# LumenBox 0.4.12: the first administrator decides one thing at a time

`/bootstrap` is a wizard. Each screen asks for one decision and says what to do. After those decisions, a review is the only step that continues, and only then does the page show the one-use code and the channel sign-in.

## What changed

**First administrator**
- When the installation is `local` and the channel Secret is still empty, the screens are: unlock with the operator credential, callback address, DingTalk or Feishu, that vendor's app id and secret together, then the review. Confirm does not start OAuth. The operator credential and the one-use code are never on the same screen.
- A callback address or a channel that is already set is skipped. When a channel can already sign someone in, the page is the one-use code and the sign-in button.
- Off `local`, the page only names the Secret's variables and the callback paths. It does not ask for the operator credential.
- Choosing the port-forward or any other loopback or plain `http` origin warns on that screen before it is saved. DingTalk and Feishu servers cannot call that address.

**Also since 0.4.11**
- A viewer who signed in here can watch a desktop and cannot drive it.
- Sign-in has a limit on tries, an Origin check, a content security policy, and a session bound to its browser. Desktop watchers get a ticket, an idle limit, and a record of who watched.
- The host checks or pins the box it talks to. A box token can be rotated, and every token is on the record. The reconnect handshake is held to the official Noise IK vectors.
- An activated person is on the roster at once, with their box and one agent, and is told when that assistant is ready. A department's press shows its estimate first and its computers' progress live.
- A direct message to the shared bot reaches the writer's own agent. `@Name` means one person they may reach, and an agent can reach its own person in the chat.
- An Admin publishes a skill once and every box of the organisation has it, read-only. The skill brings its tool and its sign-in. A member can offer a skill.
- A file a member sends their own agent reaches it, and a file it makes comes back.
- An Admin cannot take a member's personal computer, and every such act is recorded first. An Admin reads only what is in a box they may enter.
- Release acceptance can walk an upgrade, including the old app's refusal of newer data.

## Upgrading

Data from 0.4.11 loads unchanged. On Kubernetes (`organisation.yaml` or `control-plane.yaml`), update the Deployment container `image` and `AGENTBOX_IMAGE` to `fakechris/lumenbox:0.4.12`.

## macOS downloads

- Apple Silicon: `LumenBox-0.4.12-arm64.dmg` or `LumenBox-0.4.12-arm64-mac.zip`
- Intel: `LumenBox-0.4.12.dmg` or `LumenBox-0.4.12-mac.zip`

These builds are **not Apple notarized**, so macOS may block the first opening. Either right-click LumenBox and choose *Open*, or run `xattr -dr com.apple.quarantine /Applications/LumenBox.app`.

`SHA256SUMS` identifies the exact published files.

## Box image

`fakechris/lumenbox:0.4.12` — linux/amd64 and linux/arm64. Once the app is running, it offers *Apply update* for the box.
