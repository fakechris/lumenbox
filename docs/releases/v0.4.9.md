# LumenBox 0.4.9: decisions you can find, tasks that may do the work

A fix release. What waits on you is easier to find and to answer, an agent no longer stops at "propose" when you asked it to produce a file, and routines report only their own runs.

## Fixes

**Needs you**
- A decision is asked where you are: the work panel's foot has *Count it as done*, *Put off* and *Stop this work*, with a line saying what each leads to. The status picker is gone; level and waits-on moved to Diagnostics.
- Inbox rows that wait on a piece of work carry the same buttons as its card. Rows that are not about one piece of work (a box update, a model out of usage, team memory, a paused routine, a spend pause) have a *Go to …* button and open the same place.
- What each button on a needs-you card or a delivered result does is a visible line under the buttons, not a tooltip.
- An agent's unread count no longer adds its side threads, which the page never opens, so a count that could not be cleared is gone.
- Buttons look like buttons: the expected answer is filled, the others raised.

**Tasks and how far an agent goes**
- A task that asks for a file — "analyse the logs and write the counts to report.csv", "summarise the incident into postmortem.md" — is now the work itself, not a proposal. Before, words like *analyse* or *summarise* set it to "propose only" and the agent handed back a plan instead of the file.
- Words like *build* and *fix* count as a request only where they are an instruction ("… and build the parser"), not as nouns ("the build logs"). Negations ("do not edit or modify them") never read as a request.

**Routines**
- A routine run's result and token count are its own turns', found by the run's message id. A chat with the same agent that timed out meanwhile no longer fails the routine or bills it its tokens, and a waiting webhook gets the run's own reply.

**Sign-in and boxes**
- A stale first-run sign-in link no longer leads nowhere; the Boxes page shows its host guidance in full; tasks on a personal computer are shown to the right people.

## For benchmark and evaluation runs

- `AGENTBOX_EVAL=1` marks an unattended evaluation run: a tool the work needs and cannot have (no desktop in a benchmark container) is routed around — the agent is told, tries another way or says it cannot — instead of the turn waiting for a person. Installations never set it; with a person there the turn still stops and says what to restore.
- docs/105 and `scripts/harbor/` run LumenBox on a public terminal benchmark (FrontierHarness v1.1, via Harbor). docs/evals carries the first measured internal evaluation reports, one per model per day.

## macOS downloads

- Apple Silicon: `LumenBox-0.4.9-arm64.dmg` or `LumenBox-0.4.9-arm64-mac.zip`
- Intel: `LumenBox-0.4.9.dmg` or `LumenBox-0.4.9-mac.zip`

These builds are **not Apple notarized**, so macOS may block the first opening. Either right-click LumenBox and choose *Open*, or run `xattr -dr com.apple.quarantine /Applications/LumenBox.app`.

`SHA256SUMS` identifies the exact published files.
