# 外部监督者：一个委托人，不是一双手

**状态：2026-11-02 定稿并实现**（INV-1506..1509 已合并；INV-1510 兼容测试见 §5；途中修复 INV-1511）。这一页同时是对外 MCP 门
（`src/web/mcp-server.ts`、`mcp-tools.ts`、`mcp-contract.ts`）的归属文档——此前没有一页说清它。

## 0. 决定，一段话

一个在我们之上"看着目标达成"的 agent——我们自己的看门狗，或别人写的 super-agent——是一个**委托人**：
它持一枚 MCP 令牌，令牌属于一个人；它经门派活、读记录、在少数事情上发言。它**不是一双手**：不把端点
守护进程装进 box，不直接驱动桌面，不判定完成，不扩大授权。理由是 docs/89 §8：两道门，没有第三层。一个
有记忆、有工具、能直接动 box 的上层，就是藏起来的第三层权限。

分工一句话：**发生了什么由我们的记录说了算；还值不值得继续由监督者判断；"做完了"由我们的验证会话判定。**

## 1. 为什么不直接用一个现成的 super-agent 当核心

- 现成的上层大多把循环放在云端、把执行环境当成被接入的端点；它们自己承认的开放问题——上层被攻破则所有
  端点被接管、凭据会进上下文、跨权限边界的协作——正是我们 box 与出站层的答案。把它们放在核心，等于把
  这些答案让出去。
- 它们最有价值的机制（授权书、观察档、按目的限制出站、出站收据、长命令转后台、后续消息归正在做的人、
  注意力阶段表）我们已经有了。
- 我们真正缺的只有一样：**编排器之外的一圈控制**。目标模式的闸门与验证会话都在编排器内部；编排器卡住或
  一件工作无声地停滞时，没有东西从外面看。

所以：合同先行；自己写一个很薄的看门狗做第一个客户端；别人的上层做第二个客户端，验证合同够不够。

## 2. 门今天有什么

| 工具 | 做什么 | 门 |
|---|---|---|
| `assign_task` | 派一件工作给团队，立即返回任务 id | 任务以调用者为 requester 创建，授予 explicit 授权书；支持 Idempotency-Key |
| `task_status` | 任务状态、结局、历史；无 id 时列出自己未结束的 | 只读；任何持令牌者可读任何任务（任务板是团队的共享记录） |
| `list_agents` | 团队名册 | 只读 |
| `run_on_box` | 在 box 上跑一条命令 | 以调用者身份过同一道策略门；危险命令给令牌持有人发确认卡片；执行记在 `mcp:<principal>` 名下 |
| `box_screenshot` | 当前桌面截图，存到 box 上给路径 | 只读 |

每个调用都有主人：令牌签给一个委托人，计费、预算、审计、审批都落在这个人身上。

改动世界的工具在 tools/list 里都多一个 `idempotency_key` 参数（INV-1512）：通用 MCP 客户端不能按调用设 header，模型要能看见并填上它；带同一个值重试返回第一次的答复。header 与 `_meta` 仍然优先。

## 3. 合同要补的四样

**3.1 结构化记录（INV-1506，已建）。** `task_status` 在文本之外返回 `structuredContent`：结局（state + reason）、
注意力阶段（同一张阶段表）、授权书与其当前复核结论、最近的历史；任务是目标时附 pursuit 摘要（状态、
暂停原因、清单逐项裁决、花费与上限、实验账本末尾、上次验证）。监督者读事实，不读措辞。文本不变。实现：`mcp-record.ts`（`taskRecord`），工具的 `runWithRecord`；阶段读的世界与注意力页同一个 `stageWorldOf`；读取从不复核授权书（复核会写），只报告板上存的 valid / stale / withdrawn。

**3.2 目标从门进来（INV-1507，已建，docs/74 §9）。** `goal_start` 走与 `/goal` 同一个 `goalCommand`：同样的权限、上下文、
阻塞检查，必须带幂等键。`goal_control` 只对自己发起的目标有效：可暂停、可清除；**只能续自己暂停的**——
系统因预算、重复、空转、验证失败叫停的，续跑是人的决定。加预算、确认清单命令、替换目标不经门。

**3.3 变更流（INV-1508，已建）。** `watch` 长轮询：自游标之后的阶段与目标状态变化，没有就等到有或超时（≤30 秒）。
不做 SSE，不做宿主主动外呼——外呼是一个新的出站面，要另外论证。实现：`mcp-watch.ts` 的 `ChangeFeed` 挂在任务板的 onChange 上，有界环（2000 条），只在状态、阶段、目标状态或暂停原因变化时记一条；游标落在环外返回 `reset`；调用方挂断即释放监听。任务的创建不在板的变更流上，它的第一次变动才是第一条事件；阶段在任务变动时读，回合开始或结束不产生事件。

**3.4 看门狗（INV-1509，已建，docs/91）。** 独立进程、自己的令牌，只经门。确定性规则：工作中但长时间无变化；系统暂停
后长时间无人处理；验证连续失败；门不可达。可选的模型判断默认关。动作只有三种：暂停它自己发起的目标；
`raise_attention`——在任务上写一条备注并进入"需要你"条，经我们的出站目的门以通知发出，同一原因有冷却；
门不可达时执行一个本地命令。实现：`src/watchdog/`（client、rules、main），`agentbox watchdog`；`raise_attention` 写 `task.flag`（task-flag.ts，状态一动即失效、同一备注 6 小时内同一面旗），进入注意力 "flagged" 条目与任务所在聊天的 notice；`task_status` 无 id 时可 `scope: all`。

**3.5 独立监督者（INV-1518，已建）。** `agentbox supervise --objective "…" --token-file … [--agent] [--budget] [--model gpt-6.1-sol]`：
OpenAI Responses API 上的一个薄循环（`src/supervisor/`），只拿五个门工具——goal_start、task_status、goal_control、
raise_attention、list_agents。不给 watch：等待是宿主的事，模型只在目标记录变化或长时间没动静时被叫醒。也不给碰
box 的工具。goal_start 的 agent 和 budget 由运营者给，模型看不到这两个参数。每次运行写 `~/.agentbox/supervisor/<run>/`
下的 transcript 与 summary，里面不含任何令牌或 key。

这三条都是真实模型跑出来的，不是事先推出来的：
- 模型给可选的 agent 填过空串和 "coordinator"；
- 模型自己编过一个没人要的预算；
- 模型自己拿 watch 来等，白花调用。

改完后，同一目标只用两次模型调用：一次启动，一次一句话。门这边也随之改了：空的 agent 当作没填；不认识的
名字拒绝，并列出团队。

**在 app 里（INV-1527、INV-1528）。** 看门狗和监督者合在一个 `agentbox supervision` 子进程里，由桌面 app 管理，用户不装任何服务。设置在 Settings → Supervision：
- 看门狗的开关与阈值；
- 监督者的 provider 与模型，复用 Settings → Model 里已设的 key——OpenAI 的 gpt-6 走 Responses，其余走 app 的 provider 层；
- 默认 agent、预算与上限。

同一页可以发起、查看、停止运行；被监督的目标在任务列表里标 "supervised"。运行以文件排队（`~/.agentbox/supervisor/`），读回时再脱敏一次。

## 4. 监督者不能做的

| 不能 | 因为 |
|---|---|
| 判定"做完了" | 完成由另一个会话验证（docs/74 §3.4）；监督者是又一个会自审的执行者 |
| 续跑系统叫停的目标、加预算 | 叫停是闸门的结论，越过它就是让闸门失效 |
| 修改门、预算、拒绝 | 这些在代码里（docs/89 §14）；监督者能提议的只有团队可覆盖的措辞，由人批准 |
| 把自己的守护进程装进 box | 第二个权威，绕过 boxd 的门与记录 |
| 读记忆、会话正文、文件全集 | 门给的是一台电脑和一支团队，不是我们的内脏（`mcp-server.ts` 文件头） |

## 5. 兼容测试（INV-1510）

用一个别人写的上层做第二个客户端：一次性隔离容器，只配门地址和一枚专用令牌，不挂主人 home。

**2026-11-02 结果：协议层通过。** 对方运行时的 MCP 客户端就是官方 SDK（streamable-http、静态 headers），同样构造的
探针在一次性容器里走完整个合同（watch、goal_start、结构化 task_status、goal_control、raise_attention），门这边无需改动。
缺口一处：`idempotency_key` 能作参数用，但没有工具 schema 声明它（INV-1512 候选）。完整原型未跑：Docker 磁盘满；
本测试不放模型 key；原型由 GitHub 驱动，需要专门账号。这三样都由运营者决定。
