# LumenBox 是什么：分层、理念、决定、里程碑——一页说清楚的系统论

这个系统是演化出来的：89 篇设计文档、每篇记录一个机制或一次决定（docs/INDEX.md），但没有一篇把它们
串成一个论证——我们在做什么、为什么这样分层、哪些决定定了调、哪些路明确不走、走到了哪一步。读一篇
外部的"超级 agent"设计文章（2026-11-01，分层清楚、决策明确）之后，Chris 要求补这一篇。它不新增机制，
只把已经做出的决定按一个逻辑摆出来；每一节指向真正规范的文档，冲突以那些文档为准。

## 0. 一句话

**给每个 agent 一台持久的 Linux 工作站，让一支 agent 团队在上面替一个团队的人干活；人从桌面 App、
聊天门、Webhook 指派工作，所有动作走同一套记录、同一套门、同一套预算。** 单位是三个：**box**（一台带
每-agent 桌面的真机器）、**turn**（一个 agent 收到什么、想、用工具、停下）、**record**（每一轮真正做了什么，
存成数据而不是 agent 对自己的总结）。docs/02 §1。

## 1. 理念：五条，按它们在事故里被证明的顺序

1. **记录是可信的，别的都不是。** 工具流量存成数据；agent 不能宣称它没做的工作，因为宣称和证据是两样
   东西。桌面动作带效果证据（邻域像素差、后置条件、送达五态），浏览器写入有 write path，交付物引用由
   host 核验。docs/02 §4、docs/49 A1/A3/B1。
2. **失败要响。** 静默的坏和崩溃同等严重：`unknown` 永远不映射成成功；读不到控件树是 `error` 不是空
   列表；一次投递失败是 attention 项不是日志行；ratchet 让大文件只能变短。这个系统里一半的机制存在，是因为
   某次失败曾经悄无声息（docs/19、docs/26、docs/solutions/）。
3. **人永远不被锁在外面。** 桌面可以接管（USER_IN_CONTROL，agent 必须停手）；box 和数据在人的机器上，
   文件系统就是数据库（docs/03 §8、docs/05）；任何自动化都有一个"本来会做什么"的 observe 档（docs/29、INV-1458）。
4. **权限只有两道门，中间没有第三层。** 外门是安装的（你是不是我们的人），内门是 box 的（这台机器的持有者
   能到哪，里面的一切就能到哪）；渠道和 agent 不带自己的权限集；同一 box 里的 worker 在"能到哪"上一律平等。
   这条原则一次性消灭了"企业飞书 / 个人飞书"这类伪实体——一个新门只问它的人和哪个 box 的人"权限相同还是
   隔离"。docs/22 §0。
5. **agent 做判断的事，系统做铁轨。** bot 自己打包自己、新 bot 自己安装自己是本质，缺一个工具不是理由；
   系统提供的是轨道——门、预算、记录、拒绝——而不是替它伸手。规则写进 prompt 的可以被团队覆盖（docs/87），
   写进代码的门不能被 prompt 放宽。docs/29、docs/87。

## 2. 分层：四层，每层只回答一个问题

```
 人 ───► 门（doors）────► 宿主编排器（host）────► box（boxd + 桌面）────► 外部世界（egress relay）
         "谁在说话、          "这一轮该谁做、            "动作真的落地了吗、         "凭据不出 box、
          说给谁"             做了什么、能不能"           人在不在用这台机器"          出站有没有被拒"
```

| 层 | 代码 | 它拥有的概念 | 它明确不做的 |
|---|---|---|---|
| **门 / 渠道** | `src/channels`、`src/web`、`src/control` | 身份（principal）、地址、消息 id、ingress 账本；出站的目的（result / attention / answer / ack / notice）与收据 | 不路由决策、不带权限、不改消息内容 |
| **宿主编排器** | `src/host`、`src/agents` | turn 循环、bus 与 lane、registry（box 归属与团队的唯一定义）、prompt 装配、记忆、技能索引、任务板、授权书（mandate）、策略门、预算、目标循环、决策模型开关 | 不执行工具本体（在 box 里）、不碰像素、不保存 agent 的自我总结 |
| **box** | `src/box`、`src/boxd`、`docker/box` | 每-agent 一个 X 桌面、浏览器（CDP）、shell 与 job、文件、录像、控件树（box-ax）、桌面所有权租约、效果测量 | 不决定该不该做（那是 host 的门）、不保存会话状态 |
| **出站** | `src/egress`、relay | 凭据注入、解析后 hard-deny、每次调用一个凭证、拒绝记录 | 不理解内容 |

为什么是这四层而不是"路由层 + 工作层"：我们的瓶颈从来不是消息量，是**权限与证据**。把"谁能到哪"和
"真的做了没"各钉在一层（门不带权限；box 不做决定），其它层才能随便换——编排器换模型、box 从本地
Docker 换成挂载的远端机器或 personal box、门从飞书换成钉钉，都不动另外三层（docs/03 §1：三部分一个合同）。

## 3. 工作是怎么流过去的

1. **入站。** 门收到消息，记 ingress，解析地址（谁、给谁、哪个会话）。群里没点名的话由 addressed 规则决定
   是否唤醒；线程里的跟进先归正在做该 task 的 agent 判断（做 / ack / 退回一句理由），退回后才进路由
   （INV-1462）。docs/26。
2. **这一轮归谁。** bus 按 lane 排队（user 在 background 前，有饥饿提升）；一个 agent 一个会话一次一轮；
   人的消息多一个并发槽；长命令 N 秒自动转后台，job 结束作为消息唤醒（INV-1461）。
3. **能不能。** 策略门（docs/04 §15）在工具调用前判：审批、税点（taint→问人）、出站白名单、不可逆动作
   （送达/付款/删除）；工作级授权书记"谁、凭什么、多强、策略版本"，唤醒和续做前重验（INV-1457）。
4. **做。** turn 在 box 里用工具；每个桌面动作带效果证据与送达裁决；浏览器写入先观察后动；ref 身份校验
   （STALE_REF / AMBIGUOUS_TARGET）。
5. **说。** 出站按目的把门：result 要有交付物，attention 要有问题，answer 要有待答问题（INV-1459）；每条
   发送一个确定性 id 和收据，可安全重试（INV-1460）。
6. **记。** turns.jsonl（含 agent 版本 hash）、transcript、policy.jsonl、effect、usage；answer-review 给每条
   回复打标签，坏样本沉淀为 eval case（INV-1474）。

## 4. 定了调的决定（和被拒绝的路）

| 决定 | 为什么 | 拒绝了什么 | 出处 |
|---|---|---|---|
| 一个 agent 一台桌面，不是一个共享显示上的窗口路由 | 焦点是合成输入跟随的东西，共享就会撞 | 窗口路由 | docs/03 §8 |
| 文件系统就是数据库 | agent 用同一把 shell 读队友的 profile，人用编辑器也能 | 数据库、ORM | docs/03 §8、docs/05 |
| box 是权限单位，worker 在 box 内平等 | 两个 agent 在一个 box 里"能到哪"不同 = 建模错误 | 每-agent 权限集、渠道权限 | docs/22 §0 |
| 共享卷、同步守护、"一个 agent 两台机器"都不提供 | 每一个都是藏在一个 worker 里的第二个权威 | 第二权威 | docs/30 §2 |
| 第三方桌面二进制可以跑但不进产品通道 | 它绕过 boxd，所有权/税点/审批/效果账本全看不见 | 旁路的桌面工具 | INV-1482 |
| 计划是数据，不是代码 | `node:vm` 不是边界；真沙盒是第四个运行时依赖；"N 项→答案→汇总"不需要分支 | 模型写脚本在沙盒里跑 | docs/32 §9 |
| 目标模式的完成闸门不归执行者 | 自审是"停下冒充完成"的温床 | agent 自标 Done | docs/74 |
| 决策模型（Jev）是开关点，不是主模型 | 便宜、可 shadow 对比、每个点可独立关掉；它读得太字面，绝不让它产生要输入的文本 | 用主模型做所有判断；让小模型生成动作文本 | docs/85 |
| 内置 prompt 可覆盖且带基线，代码里的门不能被 prompt 放宽 | 团队要自己的措辞，但权限不是措辞 | 一切皆 prompt | docs/87 |
| 默认安全姿态：未设即 off，unknown 不重试，未声明的工具是 unsafe | 两种错的代价不对称：多问一句是一句话，重复付款是一笔钱 | 乐观默认 | protocol/idempotency.ts |
| 技能索引折叠描述而不抬上限 | 上限是每轮每个 agent 的 token；索引是为一个决定读的 | 16k 上限 | INV-760 |
| 不做：托管服务、自治机群、不受信代码的沙盒 | 一个 box、一个团队、一个主人；容器是边界，agent 有 sudo | — | docs/02 §5 |

被拒绝的路和被采纳的一样重要：它们是下一次有人提出同一个想法时的答案。

## 5. 和"路由层 + 工作层"那套设计的关系

那篇文章的骨架我们大多已经有，只是没这么叫：触发式工作（listener / routine / webhook，observe 档）；
事件两段过滤（门的规则是 fast path，模型是 slow path）；线程订阅（thread 里的跟进直达正在做的 agent）；
inline & spill（截断读取带指针、ReadHistory、Recall、技能索引只放描述）；全双工（长命令转后台、job 唤醒、
人的消息并发槽、mid-turn steering）；分渠道说话（出站目的、IM 简短、文档结构化）；看门狗（goal loop 的四道
闸、stall / repeating、attention 阶段表、box 代际）。

真正不同的两点，是刻意的：

- **我们没有一个"全局路由会话"。** 路由是代码（registry + bus + 门规则），不是一个长寿 LLM 会话。理由是
  第 1 节的第 4 条：带记忆的全局节点会变成第三层权限，而我们要的是"门不带权限"。代价是没有一个会话
  "记得所有任务"——我们用任务板、authority book 和 Recall 补，而不是一个会议记录员。
- **计算、状态、执行环境三分离我们只做了两步半。** 执行环境（box）早就与编排器分离并可挂远端（docs/30）；
  状态在文件系统，但编排器仍在主人的机器上，不在云里。原因：主人的机器就是信任边界（docs/02 §5），上云
  意味着重新回答"谁能到哪"。出站中继（INV-1477）是在不动这个边界的前提下让人从外面用自己的 box。

## 7. 系统哲学，三句

- **先写记录，再写能力。** 一个没有记录的能力在这里是负资产：它会被宣称、不会被证明。
- **边界用代码画，措辞让团队改。** 门、预算、拒绝在代码里；语气、顺序、"怎么算做完"在团队可覆盖的文本里。
- **外部读来的东西，先在自己的事故上验证，再借。** docs/14、docs/49、docs/85 每一项"借"都带着我们自己的
  测量；拒绝的也写下来。
