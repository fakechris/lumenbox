## Afternoon: the live Grok Bot box, and what we took from it

Captured the running box's state over ssh into the research tree
(`versions/0.30.0/runtime/`, analysis §9). Three things shipped from it:

- `~/reference/debugging-the-box.md` and `app-ui.md` in our box (projected from the image at
  every start, named in the computer section of the prompt): real paths only — box-doctor,
  the `/tmp` logs per display, the web app's actual controls — so an agent diagnoses its
  computer before declaring it broken and never invents a button for a person.
- A first-run turn: an agent created from the web (new-agent form or catalog) opens the
  conversation itself with a short hello and one question, on a `[first run]` cue.
- `poppler-utils` in the image (`pdftotext`, `pdfinfo`).

And one lesson the upgrade path taught: the image build's `curl | bash` for nodesource hid
a TLS failure, Debian's Node 20 (pulled by novnc) stayed, and boxd died on `WebSocket is not
defined`. `box up --recreate` caught it in its smoke test and rolled back to the previous
image. The Dockerfile now downloads the script to a file and asserts Node 22 with a
WebSocket global, so that image cannot build.

Not taken, recorded as directions: editable memory files (theirs is the store, ours a
mirror of a deduplicated ledger), per-agent action audit (our transcript has it), bot
templates that seed memories and skills through the agent's own first turn, and
teach-by-demonstration.
