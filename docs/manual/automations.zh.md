# 自动化

自己开始的工作：按定时、在某个 URL 被调用时，或在消息匹配时开始。

## 这是什么

**例行任务**是一个自己运行的 skill。它的文件写明什么时候运行：`schedule:` 表示定时，`trigger: webhook`
表示一个谁都能调用的 URL，`trigger: message` 表示匹配的消息。`deliver:` 指定接收报告的聊天。例行任务处在三种模式之一：
`off` 从不运行，`observe` 记录它本来会做什么，`auto` 真正运行。

观察模式只报告、不动手：处于 observe 的例行任务只记录它本应运行，什么都不会运行。到*自动化*标签页查看：“本应运行 N 次 · 最近一次 …”。

## 怎么做

### 在 app 里

- **新建一个：** *自动化*标签页 → *+ 新建*。给它起名字、写指令，在*何时运行*里选择按计划、webhook 或消息，
  再选它以哪个 agent 的身份运行。
- **安全地试一试：** 按*观察*看它会做什么，信得过之后再按*放手运行*。*立即运行*马上运行一次。
- **暂停或恢复：** *暂停*和*开启*。
- **查看历史：** 按*运行记录*。你会看到最近几次运行及其结果（完成、部分完成、失败、跳过、仅观察、运行中或被打断），以及接下来要运行的几次。
- **webhook 例行任务：** *显示*和*复制*给出密钥；*新密钥*会替换它。旧密钥在 24 小时内仍然有效；*立即停用*马上让它失效。
- **自动暂停：** 设置 → 团队 → 例行任务 → *连续失败几次后暂停*（默认 3 次；0 表示从不暂停）。

### 在聊天里

- `定时`（或 `automations`）：列出会自己运行的工作。
- `早报`：马上发出这个群的摘要；`早报 8点` 每天 8 点发送；`早报 关` 停止发送。
- 例行任务把报告发到 `deliver:` 指定的聊天。

### 在命令行里

```
agentbox routines runs <name> [--limit N]   # 一个例行任务最近的运行，以及它是否被暂停
```

webhook 例行任务由一次 HTTP POST 启动，发到它的 URL，并带上 `Authorization: Bearer <secret>`。

## 在哪里看结果

- *自动化*标签页：每个例行任务的模式、最近一次运行，以及被暂停的原因。
- 例行任务上的*运行记录*：它的运行历史。
- `deliver:` 指定的聊天：报告本身。

## 限制

- 连续失败 3 次（或你设定的次数）的例行任务会被暂停，以最后一次失败作为原因，直到有人按*开启*。
- 缺少密钥或连接器的例行任务不会开始：这次运行被跳过，例行任务被挂起，直到重新开启。
- 没写模式的例行任务会运行：它就是 `auto`，显示为“auto（未设模式）”。
