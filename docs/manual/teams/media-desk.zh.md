# 内容小队：一份素材，三种形式

这是一套可以照搬的内容工作设计：一份素材变成一篇长文、一篇小红书笔记和一份短视频脚本，每种形式由负责它的 agent 来写。

## 架构

`media-desk` 小队（app 里叫“内容小队”）从目录添加三个 agent。每个 agent 负责一种形式。属于同事的形式，它交给同事去写，而不是把自己的稿子删短了事。

| 角色 | Agent | 写什么 | 能碰什么 | 不做什么 |
|---|---|---|---|---|
| 长文 | Jian（主笔） | 读者会在手机上读完的文章、简报和解读 | 文件、浏览器、网页搜索、飞书文档 | 笔记或脚本 |
| 笔记 | He（种草） | 小红书笔记：标题、封面文案、正文和几个变体 | 文件、浏览器、网页搜索、飞书文档 | 声称用过自己没用过的东西 |
| 脚本 | Jing（编剧） | 口播短视频脚本：开头钩子、正文、一个号召 | 只有文件；没有浏览器 | 拍摄素材、配音、播放量 |

```
素材（链接、笔记、文件）──▶ Jian ── article.md ──┬──▶ He   ── 笔记 + 变体
                                                 └──▶ Jing ── 带停顿的脚本
                     三份都落在 /home/box/work；由你发布
```

## 核心设计

### 提示词

每个角色设定都用中文写成，每一轮都会重读（`src/host/catalog-data/experts/`）。每个设定都写明哪些形式属于同事，这样同一份素材不会被一个 agent 删短三次。三个 agent 都拒绝编造来源、编造亲身使用经历，也拒绝承诺传播效果。

### 工具与权限

- Jian 和 He 有桌面工具，外加上网能力：box 里的浏览器、`WebFetch`、`WebSearch` 和 `ReadFeishuDoc`。
- Jing 只有桌面工具；脚本根据文章来写，不根据网页来写。
- 小队里没有谁会往任何地方发布内容。发布到外部服务要经过连接器，你在 配置 → 工具 里把它设为“问我”。

### Skill

Jian 读 `khazix-writer`、`humanizer` 和 `wechat-longform`。He 读 `xiaohongshu-note`、`marketing-skills`、`humanizer` 和 `content-repurposer`。Jing 读 `short-video-script`、`content-repurposer` 和 `humanizer`。这些 skill 每个 box 都自带。

### 记忆

每个 agent 各自记住你的风格和你的读者。草稿是 `/home/box/work` 下的文件，所以同事从那里读文章，而不是从聊天消息里读。

### 凭据

起步时不需要。`WebSearch` 需要在 设置 → 模型 里填一个搜索密钥（Keenable、Brave 或 Tavily）；没有它，agent 就用 box 里的浏览器搜索。需要账号的网站，必须在那个 agent 的桌面上登录：你接管桌面，自己登录。

## 配置：最小与日常

| | 最小 | 日常 |
|---|---|---|
| Agent | Jian、He 和 Jing，在小队把它们放进的 `media-desk` 团队里 | 同样这三个 |
| 输入 | 每次请求一个链接或文件 | 一个每天早上收集素材的例行任务（自动化 → *+ 新建*） |
| 搜索 | box 里的浏览器 | 在 设置 → 模型 里填搜索密钥 |
| 交接 | Jian 写完后，你再去找 He 和 Jing | 告诉 Jian 把文章交下去；分工里能看到这条链 |
| 渠道 | 只用 app | 一个飞书群，Jian 是默认 agent |
| 发布 | 你把文件拷出来 | 仍然是你；见 *box 之外* |

## 运行成本

**依据：**尚未测量。这个安装的记录里只有小队的设置回合。2026-09-08（模型 MiniMax-M3），Jian 的设置回合用了 4.0 s，Jing 的用了 3.7 s；He 从未安装。它们的用量记录在 48 小时后被压缩，所以没有留下任何 token 数。记录里没有这个小队处理一份素材的运行，所以本页不给数字。

测量方法：在有模型密钥的 box 上安装这个小队，把 `AGENTBOX_USAGE_RETAIN_HOURS` 设得比这次运行更长，然后给 Jian 一份素材，并说“先写文章，再写笔记和脚本”。记下这个任务的 `agentbox usage --task tN`、任务历史里的实际耗时，以及当天使用的模型和价格。要算出每篇*被采纳*作品的成本，还需要你对三份文件各自给出判断（[docs/75](../../75-cost-per-accepted-task.md)）。

## 搭一个最小版本

### 在 app 里

1. 点 *Agent* 旁边的 `+`。在 *从目录添加* 下点 `内容小队`，再点 *创建这 3 个，放到 <box>*。它们会进入 `media-desk` 团队，在侧边栏里列在一起。
2. 选中 Jian，粘贴素材，并说明读者是谁。
3. 文章进了 box 之后，让 He 据此写一篇笔记，让 Jing 据此写一份脚本。
4. 打开任务：*交付物* 列出每个文件，旁边有 *下载*。

### 在聊天里

1. 在 设置 → 渠道 里，把群的默认 agent 设为 Jian。
2. 在群里发送素材。另外两种形式，分别发 `@He` 和 `@Jing` 消息。
3. 文件会随回复一起发到聊天里。发送 `看板` 查看任务。

### 在命令行里

```
agentbox agents                              # 安装后会看到 Jian、He 和 Jing
agentbox chat Jian "把这篇链接写成一篇公众号长文：……"
agentbox usage --task t12                    # 这篇稿子花了多少，有回合之后才有
```

## 运行监控

- **侧边栏：**agent 写稿时显示 `运行中`；它向你要素材或要确认时显示 `等你处理：…`。
- **任务 标签页：**每个请求是一个任务。进入 `review` 的任务在等你的判断。“turn ended; not closed because …”表示还没有人检查结果。
- **卡住：**以 `incomplete` 结束的回合碰到了单轮上限。网页一直加载不完时会这样。任务历史里出现“flagged for a person”一行，表示一个小时没有变化。
- **任务卡片：***交付物*（不是 PDF 的 `.pdf` 会被拒绝，必须重做）、*把关* 一行，以及 Jian 拆分工作时的 *分工*。

## box 之外

- 发布：公众号、小红书账号和视频号都是你的。小队负责写，人负责发。
- 事实：agent 会标出自己无法确认的内容，由你决定这样够不够。
- 你自己添加的图片和引文的版权。
- 如果小队在群里工作，需要在飞书或钉钉的开发者后台注册一个应用。

## 扩展

- 加一个每天早上为 Jian 收集素材的例行任务，先让它在“观察”模式下跑一周。
- 稿子依赖数字时，加上 `xi`（分析师）。
- 小队没覆盖的渠道，从模板架上直接套用一个现成模板。
- 把调好的 Jian 存成模板，让另一个 box 一开始就带着你的风格。
