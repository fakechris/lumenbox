# 起步团队：一个随时待命的协调者，加一个研究员、一个运维和一个审查者

本页介绍新安装自带的四个 agent：它们组成一个团队，回应你的群，查明情况，并检查自己的工作。

## 架构

新安装在一个 agent 都没有时，会创建这四个。它不是目录里的小队：你不用添加它，删掉其中一个也不会自动补回。Ada 排在第一个，所以没有点名任何人的渠道消息由她回应。

| 角色 | Agent | 做什么 | 能碰什么 | 不做什么 |
|---|---|---|---|---|
| 协调者 | Ada | 回应你，小事自己做，其余的交给队友 | 所有工具，包括创建和修改 agent | 把一行就能做完的活交出去 |
| 研究员 | Rex | 顺着来源追到源头，把发现写进文件 | 浏览器、文件、shell | 组建团队，替你遗忘记忆 |
| 运维 | Ops | 安装、构建、运行脚本、移动文件 | 首先是 shell，其次是文件 | 组建团队，替你遗忘记忆 |
| 审查者 | Vera | 复现队友的说法，报告哪些站得住 | shell、浏览器、读文件 | 写文件，使用外部服务 |

```
chat group / app ──▶ Ada ──┬── small job: does it herself ───────────────▶ reply
                           ├── "find out" ──▶ Rex ── notes in /home/box/work
                           ├── "make it run" ──▶ Ops
                           └── "is it true?" ──▶ Vera ── what was verified, what was not
```

## 核心设计

### 提示词

四份描述用英文写成，每一轮都会重新读取（`src/host/orchestrator.ts` 里的 `STARTER_TEAM`）。每份描述讲的是这个角色的工作会怎样出错，而不是它有多能帮忙。Ada 被告知：自己做比交接更快时，就自己做。她会提议一个目录里的 agent，而不是自己凭空造一个。

### 工具与权限

- Ada 拥有所有工具，包括 `CreateAgent`、`UpdateAgent` 和 `Forget`。
- Rex 和 Ops 拥有除组建团队和遗忘之外的所有工具。
- Vera 的工具和他们一样，但去掉了 `write_file` 和 MCP 服务：能改动自己所检查内容的审查者，就不再是审查者。
- 在 配置 → 工具 里修改其中任意一项；任务卡片上的*把关*一行显示每一步的把关结论。

### Skill

起步 skill 和 hub skill 随每个 box 一起提供（见[随附的 skill](../reference-skills.zh.md)）。在聊天框里输入 `/` 可以看到它们。Rex 会用 `deep-research`；需要编码引擎时，Ops 会用 `engine-check`。

### 记忆

每个 agent 都有自己的记忆。它的发现写进 `/home/box/work` 下的文件，下一个人就能读到。一条对四个 agent 都有用的事实，要等一个人在 设置 → 团队 → 团队记忆 里确认后，才进入团队记忆。

### 凭据

团队本身不需要凭据。渠道需要平台应用的凭据（设置 → 渠道）。`WebSearch` 需要一个搜索密钥（设置 → 模型）。Notion 这类连接器需要它自己的登录（设置 → 渠道 → 连接器）。缺少凭据的工作不会开始，而是显示一张“Before … can start”卡片。

## 配置：最小与日常

| | 最小 | 日常 |
|---|---|---|
| Agent | 大部分由 Ada 一个人做；另外三个在旁边待命 | 四个都用；如果你从没见过交接带来好处，就只用 Ada |
| 从哪里找它 | app | 一个飞书或钉钉群，Ada 是默认 agent，设为*群：仅在被点名时回复* |
| 审查 | 你自己读答案 | 有人会检查的工作，指定 Vera 为审查者 |
| 工具 | 保持出厂设置 | 在很多人都能发言的群里，把 Ada 的 `bash` 设为问我 |
| 监督 | 看门狗，默认开启 | 再加上每个 agent 的每日花费上限（设置 → 团队） |

## 运行成本

**依据：**[docs/83](../../83-team-vs-single-eval.md)（INV-1340）里的实测对比，于 2026-10-24 用出厂状态的这个团队运行。它使用 MiniMax（中国）提供商和 MiniMax-M3.1-Flash 模型，在一个临时 home 和一个专用 box 里运行。原始文件是 `research/2026-10-24-inv1340/eval.json`。该文件记录的输入 token 包含缓存 token，且没有拆分。所以金额按本安装配置的费率给出一个区间（每百万 token：输入 0.30，输出 1.20，缓存读取 0.06）。上限把所有输入都当作未缓存；下限把所有输入都当作缓存读取。

| 场景 | 参与工作的 agent | 时间 | 模型调用 | 输入 | 输出 | 金额 |
|---|---|---|---|---|---|---|
| 根据互相矛盾的来源写一份简报（`brief`，第 2 次运行） | 只有 Ada | 96 s | 18 | 464,859 | 16,125 | 0.05–0.16 |
| 对照文件核查一个说法（`verify`，第 2 次运行） | Ada 和一个队友，2 条消息 | 97 s | 16 | 325,531 | 10,810 | 0.03–0.11 |
| 11 个任务的平均值，团队 | — | 641 s | 61 | 输入输出合计 6.7M token | | — |
| 11 个任务的平均值，一个拥有相同工具的 agent | — | 316 s | 34 | 输入输出合计 3.5M token | | — |

对比的发现：11 个任务里有 8 个由 Ada 独自完成，这时团队的成本和单个 agent 一样。每次交接要多花 3 到 10 倍的调用和 token，而审查者看不出质量有任何提升。团队典型的失败是根本没有答案，而不是答错。这就是日常一栏写“只用 Ada”的理由。

## 搭一个最小版本

### 在 app 里

1. 带着模型密钥启动 LumenBox。第一次启动会创建 Ada、Rex、Ops 和 Vera。
2. 在侧栏选中 Ada，写下你的请求。
3. 可选：在 配置 里，给四个 agent 的*团队*都填上同一个团队名，这样它们会列在一起。

### 在聊天里

1. 设置 → 渠道 → *添加渠道*，选择 `feishu` 或 `dingtalk`，粘贴应用凭据。
2. 在该渠道那一行，保留 Ada 为默认 agent，并选择*群：仅在被点名时回复*。
3. 设置 → 团队 → *新建邀请码*；在群里，每个人发送 `bind <code>`。
4. 在群里 @ 这个应用并提出请求。`团队` 列出这四个 agent，`看板` 显示看板，`/help` 列出所有命令。

### 在命令行里

```
agentbox web                       # 第一次启动："created Ada, Rex, Ops, Vera to start with"
agentbox agents                    # 这四个 agent 及其描述
agentbox chat Ada "<request>"
agentbox usage --day 2026-11-06    # 这一天花了多少
```

## 运行监控

- **侧栏：**写着 `Waiting for you: …`（等你处理：…）的那一行，就是要你回应的。它表示一个问题、一个确认、一个交给你的桌面、一个花费上限，或者一个正在歇息的提供商。
- **任务 标签页：**群里的一个请求会变成一个任务。停在 `doing` 且没有新历史记录的任务，就是该看的那个。
- **卡住：**在 docs/83 里，团队失败的方式是一直没有收尾：交给 Vera 的工作十分钟内没有回来。看门狗的一行“flagged for a person: …”标记一个一小时没有变化的任务。以 `incomplete` 结束的一轮，碰到了每轮 60 次模型调用的上限。
- **任务卡片：***分工* 显示 Ada 或队友发起的每个分支，以及它是否已回报。*配置版本 vN* 显示这项工作是按哪一版设置运行的。

## box 之外

- 飞书或钉钉应用：由有权添加应用的人在该平台的控制台注册，并授予渠道页面列出的权限。
- 谁可以和团队对话：邀请码，以及 设置 → 团队 里的角色。
- 谁说完成：你，在 任务 标签页上，或在聊天里发 `可以`。Ada 说的“finished”不等于完成。
- 搜索密钥和连接器登录：它们在 LumenBox 之外付费或归属。

## 扩展

- 工作需要时，添加一个目录里的 agent：Ada 提议，你同意。
- 长期工作可以启动一个受监督的目标（设置 → 监督）。
- 代码工作加上[研发小队](ship.zh.md)，内容工作加上[内容小队](media-desk.zh.md)。
- `agentbox skill install` 让 Claude Code 或 Codex 通过 MCP 把工作交给这个团队。

## 本页依据的那次运行

- 最小版本：2026-11-06 在一个全新的空 home 里复现，使用 `agentbox web --no-box` 和一个没有密钥的脚本化模型。第一次启动打印了“created Ada, Rex, Ops, Vera to start with”，app 列出了这四个 agent。没有复现的部分：真实模型的回复、聊天里的步骤（需要一个已注册的飞书或钉钉应用），以及任何成本。
