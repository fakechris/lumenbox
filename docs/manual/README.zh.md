# LumenBox 使用手册

[English](README.md) · 中文

怎么用 LumenBox：你会遇到的每样东西各占一页。安装请先看 [docs/37](../37-onboarding.md)；想知道某样东西是什么、在哪里找，就来这里。

每一页的结构都一样：它是什么，在 app 里、在聊天里、在命令行里分别怎么做，在哪里看结果，它的限制，以及接下来读什么。用词遵循[术语表](../glossary.md)。设计记录说明*为什么*；这本手册说明*怎么做*。

## LumenBox 是什么

你自己的一支 AI 智能体团队，每个智能体都有一个真正的沙盒可用。你可以从桌面和聊天 app 找到它们，随时接管，并且凭记录而不是凭它们自己的话来相信它们。下表是 [docs/02 §1.1](../02-product.md#11-how-it-differs) 的简写版，那里写明了每一行靠什么来问责。

| | LumenBox | 单个编程智能体 CLI | 托管智能体平台 |
|---|---|---|---|
| **沙盒** | 一个 Linux 沙盒，每个智能体一个桌面，比任何会话活得都久 | 本机，只用于一次会话 | 每次会话一个沙箱，会话结束就没了 |
| **在哪里找到它** | app，以及飞书、钉钉等聊天 app；同一个人在所有地方都是同一个人 | 启动它的那个终端 | 一个 API 和一个控制台 |
| **团队与接管** | 有名字的智能体互相发消息、互相委派；你随时可以接管一个桌面 | 只有一个智能体；接管就是打断它 | 智能体是 API 对象；没有共享屏幕 |
| **记录** | 每一轮的工具调用和结果，都保存在本机上 | 一台笔记本上的一份对话记录 | 由厂商保存的会话历史 |
| **谁来说“完成”** | 你，凡是有人要检查的工作都由你决定 | 智能体自己，在它停下的时候 | 运行的状态 |
| **在哪里运行** | 默认在本机上；控制平面可选 | 开发者的本机 | 厂商的云 |

## 边界

每一条都是“看起来像另一样东西”的一样东西，以及到哪里确认你手上是哪一种。

- **沙盒在运行，不等于智能体在干活：** 沙盒可以开着，而每个智能体都闲着或已暂停。看侧栏：底部显示 `沙盒在线`，每个智能体那一行显示运行中、等你处理或 `paused`。
- **结果交付了，不等于工作被验收：** 一个请求在结果交付时结束，记录写明没有人验收过它。只有你的一句话会改变什么时，它才等你：有别的工作在等它，交出了文件，你要求先看或写了验收标准，它没做完就被交回，或者检查无法判定。7 天没人回应的结果会自己结束，除非有别的工作在等它。在收件里查看：每个等你的结果都写明是哪一种情况。
- **智能体的提议，不等于已经认定的工作：** 智能体提议的任务带着 `proposed` 标签，直到有人同意去做。看这件工作的面板：它写着你同意之前不会开始，旁边是 *同意去做*。
- **导入模板，不等于有了一个能干活的智能体：** 导入会新建一个智能体，它在第一轮安装自己的配方，并索要它需要的东西；群只能通过渠道找到它。在这个智能体的聊天里找“开始前需要”卡片，并在设置 → 渠道查看它的默认智能体。
- **观察模式只报告、不行动：** 处于观察模式的例行任务只记录“本来会运行”，实际什么都不运行。在自动化里查看：这个例行任务的运行记录写着 *已观察*。
- **保存的配置，不等于正在运行的配置：** 改动从智能体的下一轮起生效。看配置旁边的标签：`config v3 · v4 next turn`。
- **机主不是管理员：** 机主是你的个人安装（本机上的桌面应用）里唯一的人；管理员管理组织，组织是另一个独立的安装。个人安装永远不会让第二个人加入。在设置 → 团队 → 人员查看：它显示 Owner · 机主，或者显示角色，不会两者都显示。
- **“一直允许”不是一揽子同意：** 它只允许那一个确切的操作，只对那一个智能体，直到你撤销为止。在设置 → 我的 → 长期确认查看。

## X 和 Y 有什么区别？

**团队、小队和默认智能体。** *团队*是给同一个沙盒里的智能体贴的标签，让它们列在一起；一个智能体最多可以在 5 个团队里。*小队*是目录里的一个条目，一步添加多个智能体，作为一个团队。*默认智能体* 负责回答渠道里没有点名任何人的消息；你在设置 → 渠道里为每个渠道分别设置它。

**目标和任务。** *任务*是看板上的一项工作，有状态和历史。*目标*是处理一个任务的一种方式：`/goal <text>` 先起草一份检查清单，一轮接一轮地推进，到预算时暂停，检查通过时完成。每个目标都挂在一个任务上；大多数任务没有目标。

**skill、模板和目录智能体。** *skill* 是沙盒里的一个 `SKILL.md` 文件：请求匹配时智能体会读的说明。*模板*是一个完整保存下来的智能体——人设、skill、例行任务和约定——套用它就会新建一个智能体。*目录智能体*（代码里叫 `expert`）是目录里的一个条目，对应一个带有一组工具和 skill 的智能体；添加它就会建出那个智能体。

**看门狗和监督者。** *看门狗*默认开启，只负责提醒：工作停滞不动了，或者系统停掉的某个目标没人去看。*监督者*是可选的：另一个模型替你启动一个目标，并一直盯到结束。两者都不能把工作标为完成，不能提高预算，也不能碰沙盒。

**渠道和沙盒。** *渠道*是人找到智能体的途径：聊天平台上的一个应用，比如一个飞书应用。*沙盒* 是智能体干活的地方：一个 Linux 环境，每个智能体一个桌面。渠道通向一个沙盒；一个沙盒可以有多个渠道。

**回忆和档案。** *回忆*是智能体用来搜索自己记得的内容的工具，按字词也按含义搜索。它的*档案*（沙盒里的 `profile.md`）是同一份记忆的只读副本，由主机重写；在那里做的修改会丢失。智能体对*你*的了解在设置 → 我的 → 关于我。

**确认和工具权限。** *工具权限*在工作开始前设定：智能体能不能用某个工具，或者用之前必须先问。*确认*是对某一次请求的当场回答。“先问我”权限是会弹出确认卡片的原因之一。
