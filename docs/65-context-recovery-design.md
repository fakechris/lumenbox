# 65. 上下文恢复方案（提案）：新会话、干净会话与任务重建

本文记录 2026-09-22 讨论后的设计建议，**尚未批准为产品规范、尚未实现**。current 表示这份讨论记录未被取代，不表示命令已经可用。不替代 docs/05 的数据规范、docs/22 的身份权限规范，也不改写 docs/24 的历史判断。实施前须按 docs/13 审查标识符、持久格式、提示组装和验收含义；批准后在既有规范中更新单一归属，本文保留为理由记录。

代码基线：`cc71f82`。本轮只读代码与合同，新增本文并更新 INDEX；不改生产记忆、模型、运行配置或 INV 状态。不新建与 INV-142 重复的记忆里程碑。

## 1. 建议先做什么

先提供人能直接使用的恢复出口，不等待完整自动诊断系统：

1. `/new`：换话题，开始新的上下文，保留正常长期记忆。
2. `/new --clean`：诊断/恢复用的干净会话，不自动加载旧记忆、旧历史，也不自动学习本轮内容。
3. “重做这个任务”：在新上下文中重新读取原始要求与真实进度，继续同一项工作。建议命令 `/recover <taskId>`，不是普通 retry。

`--clean` 用显式 flag，不让“clean”同时表示会话标题和运行模式。第一版不另造含义接近的 `/reset`；`/clear` 暂不提供，避免混淆清屏、清历史和删记忆。UI 使用“新对话”“干净对话”“重新整理后继续”三种明确动作，与聊天命令共用服务。

**新会话不等于删除记录；干净会话不等于恢复出厂；任务恢复不等于重新执行所有步骤。**

## 2. 上游调研如何改变建议

### 2.1 OpenClaw

[官方命令表](https://docs.openclaw.ai/tools/slash-commands)区分 `/new`、原地 `/reset`、保留转录的 `/reset soft` 与 `/compact`。不能把它们统称“清上下文”。UI 与外部渠道的入口也有差异，集成时需按实际 surface 核对。

[session-memory hook](https://docs.openclaw.ai/automation/hooks/bundled-hooks#session-memory-details)启用后，在新会话/重置时保存旧会话的近期文本摘录。正常连续记忆很有用，但诊断污染时不能不加区别地执行“离开前再学习”。

[记忆来源与删除机制](https://docs.openclaw.ai/concepts/memory-provenance)支持按来源会话清除可追踪的派生产物，并阻止自动重新导入。它并不覆盖所有自由编辑、历史无来源内容和外部副本，原始转录也不是全部删除。借鉴来源关系与阻止回灌，不宣传万能擦除。

固定源码 `6ba6f0c7a7e6d4b50f4cbd14857df2c2cb3b25d8` 的 [reset cleanup](https://github.com/openclaw/openclaw/blob/6ba6f0c7a7e6d4b50f4cbd14857df2c2cb3b25d8/src/auto-reply/reply/session-reset-cleanup.ts)还处理生命周期版本校验、子任务停止、旧队列与系统通知。LumenBox 借鉴版本隔离，但不照抄清队列：我们的已受理请求必须有明确处置。

### 2.2 Hermes

[官方命令表](https://hermes-agent.nousresearch.com/docs/reference/slash-commands)规定 `/new`（别名 `/reset`）创建新 session ID 和空历史；CLI 的 `/clear` 兼有清屏与新会话。`/compress` 是压缩，不是干净重来。

[记忆文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)把长期记忆与会话分开，建议在完成任务或换话题时创建会话边界。另有记忆编辑/删除及写入审批。启用审批不自动纠正过去已写错的内容。

固定源码 `92dd3321929a915479ade608591d40de93965c7b` 的 [CLI 生命周期](https://github.com/NousResearch/hermes-agent/blob/92dd3321929a915479ade608591d40de93965c7b/hermes_cli/cli_session_mixin.py#L490)在适用配置下会启动旧会话记忆边界处理；[gateway reset](https://github.com/NousResearch/hermes-agent/blob/92dd3321929a915479ade608591d40de93965c7b/gateway/slash_commands_session.py#L155)更新执行代次、清缓存与会话状态，并中断旧会话委派。说明新会话是运行时边界，不只是一个新聊天气泡。

以上为文档和源码核对，未运行上游端到端测试；命令和插件细节随版本变化。我们的 clean/recover 是本项目提案，不是声称上游同名支持。

### 2.3 取舍

先借鉴明确的手动边界，再做自动恢复。压缩保持连续性；新会话切换连续性；clean 暂停历史依赖；recover 保留任务责任。四者不可用一个“智能清理”函数混在一起。

## 3. 本项目实际需要切断的路径

本次代码核对：

- `src/host/turn.ts` 在启动时选择 agent 记忆，同时读取会话转录、heard、共享记忆、plan/todos 和 tasks；提示重建还会再读部分状态。
- `src/host/prompt.ts` 的普通记忆在未提供 recall 时有默认回退；共享记忆另行 recall。只改启动调用不保证所有重建路径遵守同一模式。
- `src/agents/registry.ts` 的 plan/todos 按 conversation 存储；`readTranscript` 读取对应文件。不能把 plan/todos 全当真实外部执行状态：它们仍包含助手写的判断。
- `src/host/tools.ts` 存在 Recall 和 ReadHistory；不自动注入不等于工具不能再次取回。
- docs/05 §8 规定记忆镜像位于 box 的 `/home/box/work/memory/<agent-slug>/`。允许任意 shell/file access 时，隐藏 Recall 不能阻止读镜像。
- 当前 channel manager 以线程/聊天区分 conversation，且消息有持久 ID。清上下文不应改写外部收件地址或吞掉消息账本。

[部署后复审](handoff-2026-09-22-post207-answer-quality-review.md)已复现空选择回填旧记忆。工作区新增的 [Jev 第二轮实测](64-jev-memory-evaluation.md)也报告：不推荐的正文/索引仍可能展示，空提升列表不代表零曝光。这里引用其记录，没有把他人的实验冒充本轮重跑。

## 4. 三种操作的行为合同

| 数据或能力 | /new | /new --clean | /recover task |
|---|---|---|---|
| 旧会话正文与摘要自动进入 | 不进入 | 不进入 | 不整段进入 |
| 旧 plan/todos 自动进入 | 不进入 | 不进入 | 视为待核对草稿，不直接信任 |
| 普通长期/共享记忆 | 严格按相关性使用 | 不进入，含自动与手动历史召回 | 默认关闭，必要事实从任务来源重取 |
| 自动提炼记忆、共享经验、修改 learned skill | 沿既有设置，受版本与来源约束 | 关闭 | 恢复验证前关闭 |
| 权限、安全规则、有效禁止事项 | 保留 | 保留 | 保留 |
| 原始记录和已完成操作凭据 | 保留但不整段展示 | 保留但不整段展示 | 按任务核对并使用 |
| 原请求的交付责任 | 不自动抹掉 | 不自动抹掉 | 同一 task/request，新增 attempt |
| 模型和显式运行配置 | 不隐式改变 | 不隐式改变 | 首次恢复不换模型 |
| 已安装工具/skill | 正常按需 | 首版仅经批准的最小能力集 | 按任务授权与恢复阶段开放 |

普通 `/new` 必须同时修严格选择：不选可为空，不用未选内容补预算；否则用户会把“新会话还是同一套话”当成命令无效。Jev/provider 更换是独立实验，不与该语义修复混测。

### 4.1 clean 的诚实边界

clean 是“隔离旧历史与学习产物”，**不是没有系统规则，也不是安全沙箱的同义词**。

可信 host 安全策略与身份权限永远保留。项目/组织/agent 提示要区分维护者配置和自动学习产物：后者排除；无法确认来源的额外行为模板不能被当作安全规则强塞回来。启动说明列出仍加载的配置类别和版本，以便继续定位全局提示污染。

第一版 clean 建议先支持文本与明确输入的附件、必要的受控只读工具；不提供任意 Bash、通用文件浏览、desktop、外部记忆 MCP 或自动学习 skill。原因是这些工具可以绕过 host 召回，直接读取 box 中的旧镜像/日志。需要项目工具时，先做逐工具可见性和隔离设计；如果入口做不到，拒绝“已进入严格 clean”的承诺，而不是只加一句“请勿读取”。

用户明确补入某个文件后，可以将该对象作为本会话的显式来源，记录引用；不顺便开放同目录历史。clean 也不是 incognito，正常消息仍按既有规则留存，敏感数据处理不变。clean 会话以及用于此次清理的被隔离源会话，不应在退出或未来定时提炼时被自动补学；解除排除需明确动作。

正常后续 `/new` 可以回到普通模式，但须提示旧长期记忆再次启用；暂时绕开不等于永久修正它们。普通 `/new` 不应自动全局隔离之前正常会话的学习。

### 4.2 不让用户为了找回工作而复制全部旧历史

换话题后仍能看见旧任务卡和状态；模型不默认读取所有旧任务正文。host 的责任清单与模型的上下文选择分开：未完成请求仍能被人找到，但不会把每个旧主题注入新回答。

## 5. 标识与模块归属

拟议增加会话上下文版本，名称暂用 `contextEpoch`。它不是 docs/22 的 Channel incarnation：前者切上下文，后者管外部身份失效，绝不能复用或替代。

保留既有 agent/Box/Principal/ChatRef/conversation/request/task 标识。在 registry 管理的 conversation 元数据中记录活动 epoch 与模式，turn/后台工作携带启动时读到的 epoch。具体字段与磁盘格式在实现 PR 中统一更新 docs/05，不在各 adapter 各造 session 表。

建议职责：

| 归属 | 职责 |
|---|---|
| registry 的 conversation 元数据 | 活动 epoch、模式、切换记录与存储路径；不新建第二任务真相层 |
| host 的统一恢复服务 | 权限、忙闲检查、切换过程、崩溃恢复、任务恢复编排 |
| prompt/turn 共享的上下文投影入口 | 各轮及 continuation 按同一策略构建；不存在模式缺失后普通回退 |
| 现有 tools/policy dispatcher | 校验 clean 可用工具，拦住绕过召回的入口 |
| channel/app/MCP | 解析动作、确认、呈现；调用同一服务 |
| 现有任务与投递记录 | 请求归属、完成/失败/未知；不由 epoch 改成成功 |

建议转录与计划按 epoch 分区保存，旧文件原样作为 legacy epoch，避免跨 epoch 的 summary covers 混算；UI 可聚合显示，但模型读取指定版本。实现可沿现有目录扩展，最终磁盘路径以 docs/05 一处为准。旧导出、搜索、backup、bridge collect 必须适配全部版本，不能只看活动文件而漏掉历史。

每次上下文组装生成内部来源清单：epoch、mode、源 ID/版本/类别、纳入理由、排除原因、policy 版本、内容摘要哈希。默认不复制敏感全文到诊断日志；哈希也受权限和留存控制。清单用于证明“实际发送了什么”，不是每次给用户展示一张审计表。

## 6. 忙的时候怎么办：第一版先保守

首版 `/new` 与 clean **仅在目标上下文范围内无运行中、排队中、待问题/审批、委派及投递待确认工作时直接切换**。有未结责任时列出对应任务，保持原上下文，要求用户明确选择；不能悄悄清队列。

这是有意的第一版限制，不是“busy 消息排队后就当 reset 成功”。host 控制动作不依赖跑偏的模型执行，也不受模型普通工作队列无限阻塞。

“暂停后重建”的高级路径：

1. 记录幂等恢复请求，在目标范围设置切换屏障；新输入先持久入账，暂不派发。
2. 停止派发新的副作用操作，请求旧 attempt 在安全边界停下。
3. 记录已发出操作的结果；取消 await 不代表外部操作取消。未知结果留 unknown，禁止盲目重发。
4. 若仍不能确认安全边界，不宣布切换成功；给出具体待处理项，并可在隔离只读视图分析，不继续原写操作。
5. 持久提交新 epoch、模式和旧任务处置后，才把新输入分配到新 epoch。
6. 旧任务明确暂停/取消/保持旧版本继续三选一；首版不支持并行旧版本继续，避免未实现的双上下文副作用隔离。
7. 屏障期间到达的用户消息仍各有 message ID；提交失败则恢复旧归属，不能既在旧版又在新版执行。

切换本身需要 `prepared → committed` 的可恢复记录及 revision/CAS。崩溃后按记录继续或撤销未提交准备，不靠猜测哪个文件最新。命令重投用原 message ID/operation ID 去重，同一动作不连续生成多个 epoch；重复确认返回已提交结果。

### 6.1 旧结果如何处理

turn、后台摘要、Rememberer、worker、工具回调和发送路径在写入前核对启动 epoch：

- 旧助手正文/旧摘要/旧学习产物不得写进新 epoch 或当前长期记忆。
- 旧产物可保留在旧 attempt，标记需审查，不自动当作新任务答案。
- 外部动作的真实结果必须进入原 request 的操作/投递记录，不能因 epoch 旧而丢弃。
- 发送前尚未提交的旧草稿不自动发布；已发出的结果保留为已发送，不能 pretend unsent。
- 不修改 Box 全局镜像来为单个 clean 会话服务，避免影响其他正在工作的 agent。

### 6.2 多人、多个入口

复用 docs/22 的身份与授权判断。群聊有发言权不等于有重置整个共享上下文的权力。无独立私有/线程上下文时，拒绝会影响其他人的 reset，或由具备权限者确认其影响面。

app 的 `main` 在既有实现里还承接队友/调度活动，不能以“我只清了 UI”掩盖共享范围。第一版优先单人、单 agent、独立渠道会话；不能安全隔离的入口返回 unsupported。未来新增入口只调用统一服务，不复刻语义。

## 7. recover：继续同一项工作，不继承错误理解

`/recover <taskId>` 先检查调用人对原任务、来源、目标和动作的权限，之后按第 6 节停止旧执行。任务 ID、请求 ID、收件目标不变；attempt 与 context epoch 更新。

新上下文只收到：

- 原始用户要求和后续明确修正，保留原文引用。
- 必要指代指向的原消息；缺关键指代就问一次具体问题。
- 真实产物的路径/版本和必要摘录。
- 操作与投递的确定状态、未知项和有效禁止事项。
- 尚未完成的要求；每条要求能指回来源，模型推断单列。

旧 plan/todos、旧“已完成”自述不自动当真。先只读核对，不发消息、不写外部系统、不自动学习。若任务涉及未知发送或不可逆操作，先核实该动作；信息性答复不必因无关写操作的未知而完全停摆。

例：原 25 题重做，保留题目和可信材料，不带“统一工程主轴”；逐题答或说明未知。已经发出的旧答案仍有送达记录，新版作为明确修订，不抹除旧交付。

每个恢复请求最多一次自动内容修正；之后说明剩余问题和可选下一步。恢复新 attempt 遵守原预算、取消和授权，不给模型新的无限执行许可。合格后恢复正常工具前再检查有效权限，不能继承旧临时审批去执行新参数。

第一阶段先交付只读/纯回答恢复；带写操作的通用 recover 以可靠操作/回执视图为前置，关联 INV-616/417，不能拿记忆摘要替代它。

## 8. 持久污染治理：另一个动作，不塞进 /new

三种状态分开：

- **不相关**：本轮不纳入，原记录仍有效。
- **仅局部适用**：原任务要求，不是长期偏好。
- **结论有误**：撤销有效性，检查派生内容。

普通记忆记录逐步增加可追踪来源、作用域、适用对象与撤销关系。用户明确偏好、外部事实、助手猜测、episode 不能只靠同一 text 字段或调用 RememberFact 就混成同级权威。既有 kind=fact 不足以自动证明“用户明确授权成为长期偏好”；旧来源缺失标 unknown，不凭类型升级。

只保存来源 ID 也不够：压缩、合并、共享时须保留来源并集，撤销后派生索引、摘要、镜像、共享条目都可失效重建。混合来源不能精确拆分时，先停用该派生条目，从剩余原文重新生成；别静默删掉其他人的正确事实。

遗忘/纠错先显示影响范围，可回退地停用，保留原始记录；与用户要求的真正删除及留存策略分开。拒绝自动把“回答不好”变成永久删除整段记忆。停用还要作用于后续自动提炼，避免下一次 compact/定时学习又写回来。

角色/写作偏好等长期行为更改可要求用户确认；普通任务内事实不必每条弹窗。clean 提供临时隔离，纠错负责长期修复，用户不应被迫永久在失忆模式工作。

## 9. 分期与现有 INV

| 阶段 | 可独立交付 | 主要关联 | 不夹带什么 |
|---|---|---|---|
| A | 严格记忆选择、所有渲染路径统一策略、上下文来源清单 | INV-142、101 | 不同时换 Jev/provider，不声称普通新会话已有 |
| B | 空闲独立会话 /new；文本优先 /new --clean；持久 epoch 与恢复 | INV-142、611 的归属回归 | 不处理所有入口的忙时迁移，不删除旧任务 |
| C | 只读/问答任务 recover，再扩展有写操作任务 | INV-101、616、417 | 不把 unknown 当没执行，不重放副作用 |
| D | 派生记忆来源、纠错、共享与模板防回灌 | INV-142、397、415、615/612 | 不建另一套事实账本，不重写历史决策 |
| E | 基于证据的自动触发、小流量质量门禁 | INV-101、140/144 | 不用模糊跑题分数随意中断/删记忆 |

INV-600 与 docs/63/64 的判断模型实验并行但独立：promotion、filter、rank、policy 是不同职责。某个选择模型推荐了正确条目，不证明剩余内容未曝光。

本次检索确认已有 INV-142 归属，不认领整个里程碑、不把讨论变成已承诺实施，也不创建重复 candidate。实施拆分先检索其已有子项，再由人确认执行范围。

## 10. 验收：用什么输入把它弄坏

| 故障或输入 | 机械验收 |
|---|---|
| 普通新会话前，旧摘要反复要求立场稿 | 新 epoch 不包含旧摘要；正常相关记忆仍可用 |
| 选择为空/只选一条/记录没超预算 | 空可空，子集不回填；索引也不能泄漏 |
| clean 中调用 Recall、ReadHistory、外部记忆 MCP | 在 dispatcher 拒绝，不能只隐藏工具 schema |
| clean 中尝试 Bash/read_file 读 box 记忆镜像 | 首版工具不可用；扩展版须先具备实际隔离 |
| continuation、压缩、重启后重建 prompt | mode/epoch 不丢失，不 fallback 到普通 recall |
| 前台 clean，但后台 Rememberer 已在请求中 | 旧结果不发布为当前记忆；clean 原文也不被退出后补学 |
| 正在发送时 /new 或 recover | 不宣布安全成功；结果未知不盲目重发 |
| 一个任务运行、两个请求排队时 /new | 首版明确拒绝切换，三项工作均保留归属 |
| 屏障后新消息到达、commit 前后分别崩溃 | 持久入账、恢复归属一致，不漏单/双跑 |
| 同一 reset 命令重投两次 | 同 operation ID 返回同一提交，不再清一遍 |
| 旧 worker/旧问题按钮/旧审批回调迟到 | 不进入新 epoch；真实操作结果仍进原账本 |
| 群成员尝试清掉其他人的共享任务 | 拒绝越权；不改变 channel incarnation |
| 刚切换后升级回旧二进制 | 不静默加载旧污染上下文；缺能力明确失败 |
| recover 的原要求里有“继续上面第 4 点” | 精确取回引用；无法定位才澄清，不导入整段旧叙述 |
| 25 题里一题缺材料 | 其余题完成，单独标未知，不能只回接手 |
| 用户确实要求详细审查 | 仍能审查，不把“短、没术语”当质量标准 |
| 两个会话共享记忆，一边 clean、一边正常 | 正常会话不受全局开关影响；clean 不读其新写记忆 |
| dirty 项目 AGENTS/自动学习 skill 本身有坏规则 | 清单明确仍加载/已排除内容，不把失败错误归因于模型 |

确定性测试覆盖 registry/投影、tools dispatch、manager/app 入口和 scenario.test.ts 的 whole-stack episode。真实模型评测固定输入、模型、skill/config 版本，比较旧上下文、普通新会话、clean、recover；有独立留出样例、多次运行与人工可理解性评审。记录任务完成率、错误副作用、有效约束遗失、旧主题复发、误恢复率和成本。脚本模型绿灯不能替代真实质量。

“通过”的下限：全部已知机械边界通过；真实场景回答原要求；没有丢失用户约束或重复操作；随后多轮、一次压缩、一次重启仍不回灌。达不到则限制可用入口/任务类型，不宣传通用恢复。

## 11. 迁移、回滚与未采用方案

- 不就地清空 transcript/memory。旧会话惰性映射为 legacy epoch；只在明确操作时建立新版。备份和导出覆盖两者。
- 持久模式有 schema/version。旧程序不懂新 epoch 时应拒绝接管，回滚是兼容版本回滚或离线验证迁移，不是直接运行旧代码重新读旧文件。
- provider 缓存只可复用完全相同的可信前缀；不得继续复用隐藏旧历史的 provider session handle。不需要为“清上下文”清整个 provider 全局缓存。
- 扩展 task/message/evidence 字段不另建成功事实；OVP 归档使用原请求/turn/epoch 来源，不把上下文切换当新用户输入或重复来源。
- 不选“永远在旧上下文末尾反思”：仍在旧叙述里。
- 不选“每条消息完全新开”：会损坏真实追问。
- 不选“删光 memory”：损坏事实、偏好与恢复证据。
- 不选“先上自动污染检测 agent”：没有可验证的恢复动作，判断正确也无处落地。
- 不选“模型挑了什么就等于模型看了什么”：最终投影、工具和后台路径都必须检查。

## 12. 建议拍板的默认值

1. 普通 /new 保留严格筛选的长期记忆；clean 不读、不写学习层。
2. 忙时首版不自动清任务，不隐式取消；先限制空闲独立会话。
3. clean 首版采用最小工具集，不能安全隔离的能力不开放。
4. recover 保留原任务身份，先支持问答/只读，后做副作用恢复。
5. 保留原始记录；永久纠错与临时不使用分开。
6. 不先换模型；先做来源与投影修复，再固定输入比较效果。

这些是本文推荐，不代表用户已经批准。下一份实施 PR 应明确交付 A/B/C 哪一部分，不再把“新会话能建出来”汇报成“回答质量彻底解决”。
