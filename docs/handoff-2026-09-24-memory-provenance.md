# Handoff — 上下文恢复第五项：记忆来源纠错与防回灌

## 交付结果

新写入的长期记忆会记录来源消息或模板。记忆页显示来源，并允许先预览某个来源影响的全部
个人与共享记忆，再用版本号确认撤回。撤回只让派生记忆失效，原始对话记录仍完整保留。

## 为什么不会复活

- 自动提炼和 `RememberFact` 都带精确来源；编辑后的记忆继承原来源。
- 撤回在个人与共享两个层级都留下永久 source tombstone，即使其中一层当时没有派生记录。
- prompt、Recall、管理页面和 box 镜像使用同一个去重视图；混合来源记录只要命中一个已撤回
  来源，就整条失效。
- tombstone 在压缩后仍保留；registry 拒绝后台晚到、重启后重提炼、模板迁移或共享写入再次
  写入同一来源。

## 边界

旧记录没有来源字段时继续可读，并明确视作来源未知；系统不会猜测它来自哪条消息。本次不
提供删除原始对话或“撤销撤回”，因为两者都会削弱审计和防回灌保证。

## 验证

单元、路由和整栈场景覆盖了跨个人/共享撤回、过期版本拒绝、重启后仍失效、压缩后仍失效、
晚到写入拒绝、无关记忆保留，以及下一次普通会话不会再读到污染来源。
