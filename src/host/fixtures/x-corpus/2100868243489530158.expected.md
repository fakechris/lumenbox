# 多 Agent 协作的范式：协调结构的选择

多 Agent 系统的成败取决于协调结构，而协调结构可以脱离模型能力被单独设计、比较和证伪。

## 失败来自协调

多 Agent 系统的失败，多数不是模型不够强，而是系统设计问题。

失败率。MAST（Multi-Agent System Failure Taxonomy，多 Agent 系统失败分类法，加州大学伯克利分校，NeurIPS 2025）研究标注了 7 个主流框架的 1600 条以上运行轨迹，归纳出 14 种失败模式。最大的一类是系统设计问题，占 44.2%：步骤重复 15.7%，不知道任务什么时候算完 12.4%，没按任务要求做 11.8%。另外两类是 Agent 之间对不上，以及没人验证结果。

生产环境。《Coordination as an Architectural Layer》（2026 年 5 月）引述多份生产报告，多 Agent 系统的失败率在 41% 到 87% 之间，大部分归因于协调缺陷，与底层模型能力关系不大。41% 到 87% 是一个区间，本文没有逐一核对各来源报告，但方向与 MAST 一致。

我在不同任务上做过测试，最常见的失败来自组织方式选错，模型不够强反而少见。这属于个人观察，不是系统证据。

![image](https://pbs.twimg.com/media/HSe_rmJbAAArvbb.jpg)

读表结论：接近一半的失败发生在"怎么组织"，而不是"模型行不行"。

。。。

## 什么是协作范式

三个 Agent 合写一份市场报告，一个查资料，一个写，一个审。这个系统跑起来以后，先看任务的信息放在哪：查到的资料、写好的段落、进行到哪一步，是只留在各自的对话窗口里，窗口一关就没了，还是写进一份三个 Agent 都能打开的文件。再看写完一稿之后下一步谁说了算，是事先写死的顺序，是一个主管 Agent 看情况派，还是三个 Agent 自己商量。

出错的情形更能看出差别。查资料的 Agent 引错一个数字，它自己通常发现不了，审稿的 Agent 有可能发现，也可能要等人看成稿时才发现。最后是什么时候算完，审一遍就停，还是审到没有意见为止，这个条件写在哪、由谁判断。

这四个问题，状态放在哪、下一步谁定、出错谁先看见、什么时候停，在任何多 Agent 系统里都存在，而且互相独立。状态放在文件里，下一步照样可以由主管定；由主管定，出错也可以先由同伴发现。本文把它们叫作协调结构的四个变量，一种协作范式就是在四个变量上各选一个答案。

![image](https://pbs.twimg.com/media/HSfEu5bbQAANdCH.jpg)

## 该不该用多 Agent：实证边界

任务结构决定收益。Google Research 与 MIT 媒体实验室（2025 年 12 月）[[10]](https://arxiv.org/abs/2512.08296)在受控条件下比较了单 Agent 和四种多 Agent 架构。可并行拆分的任务上，中心化协调比单 Agent 提升 80.9%；严格顺序推理的任务上，所有多 Agent 变体退化 39% 到 70%。错误传播上，无协调的独立 Agent 放大 17.2 倍，中心化协调压到 4.4 倍（倍数口径以原研究为准）。我的结论是：收益取决于协调结构与任务结构是否匹配，与 Agent 数量无关。

同一结论的两个场景。给一份财报做多维度分析，各维度互不依赖，主管派活、工人各算各的、最后汇总，属于可并行任务。排一份施工计划，每一步依赖上一步的结果，多个 Agent 只会在交接处互相等、互相改，单 Agent 从头做到尾更稳。

![image](https://pbs.twimg.com/media/HSfFHDtaQAA7nIJ.jpg)

Cognition从反方变正方。Cognition 在 2025 年 6 月 [[11]](https://cognition.com/blog/dont-build-multi-agents) 主张不要做多 Agent，给出两条原则：上下文和轨迹要完整共享，不能只传单条消息；每个动作都带隐含决策，并行执行会让决策冲突。后来，2026 年 4 月，Cognition同一作者改变了自己的立场，写一篇文章《一类更窄的结构在其生产环境中可用——多个 Agent 贡献智能》，表达写操作保持单线程，并行写入的蜂群仍未见有效落地。不过两篇文章有共同点，就是写权限必须收敛到一处。

成本要算进去。Anthropic 的研究系统（2025 年 6 月）[[6]](https://www.anthropic.com/engineering/multi-agent-research-system) token 消耗约为普通对话的 15 倍，且系统间性能差异的约 80% 可由 token 用量解释。多 Agent 用更多算力换更大的信息容量，只在任务价值足以覆盖成本的广度搜索型工作上成立。

![image](https://pbs.twimg.com/media/HSfFmnQbwAANxWr.jpg)

任务能并行拆分，才值得考虑多 Agent；严格顺序依赖的任务，单 Agent 往往更好。

## 用哪种范式：五种范式

![image](https://pbs.twimg.com/media/HSfFv8xaYAE20FM.jpg)

流水线。任务按固定顺序经过一串角色，上一个的输出是下一个的输入。MetaGPT（2023 年，ICLR 2024）把软件公司的标准作业程序写进提示序列，角色之间只用结构化产物交接，每个中间结果都能单独验证。适用于任务结构事先已知的工作，比如按规格出软件；需求一变，整条线要重排。

主管与工人。一个中心节点负责规划、派发和检查，工人执行。Magentic-One（微软研究院，2024 年 11 月）的编排者维护两本账，任务账本记事实、猜测和计划，进度账本记每一步的进展和下一步派给谁。消融实验去掉完整账本，GAIA 上的表现下降 31%，账本比编排者本身更难替代。Anthropic 2025 年 6 月公开的研究系统同属这一类，主 Agent 规划后并行派出子 Agent，另设独立的引用核对环节，内部评测比单 Agent 高 90.2%，token 消耗约为普通对话的 15 倍。

群聊与辩论。多个 Agent 就同一问题各自作答，互相看答案，再改。Du 等人 2023 年的多 Agent 辩论在数学和策略推理上优于单模型，事实性错误更少。它适合收敛到一个答案的问题；有交付物的长流程会陷在互相修改里。

黑板。所有参与者读写同一块共享结构，下一个行动者按黑板当前内容选出，循环到达成共识。Hearsay-II 语音理解系统 1980 年前后就是这个结构。中科院数学与系统科学研究院 2025 年 7 月把它搬到大模型上，在常识、推理和数学数据集上与最先进的静态和动态多 Agent 系统持平，token 更少。适用于没有预定义流程的开放问题。

持久状态与文件交接。Agent 之间不直接对话，靠文件、账本或记忆库交接，前四种范式长期运行后大多会走到这个形态。Always-On Agents 综述（2026 年 6 月）编码了 435 篇文献，给每个状态项定义了六个诊断轴，权限、范围、可变性、来源、可恢复性、可执行性，并指出文献集中在积累和检索状态，很少讨论治理、恢复和放弃状态。

![image](https://pbs.twimg.com/media/HSfF1yjaMAAa66T.jpg)

## 两条通用原则

原则一：状态必须在 Agent 之外

能跑长流程的范式都把状态放在 Agent 外面：Magentic-One 是账本，黑板是黑板，最后一种是文件系统。原因有容量和可验证性两个。任何一个上下文窗口都装不下整个任务的历史；状态在 Agent 内部时只有它自己看得见，出了错也只有它自己能发现，而它通常发现不了。一个 Agent 既写又审，等于让同一个上下文给自己打分。

协议层的现状是，Google 2025 年 4 月发布的 A2A（Agent2Agent，Agent 间通信协议）[12]把 Agent 之间的交互定义为任务生命周期，状态包括提交、进行中、需要输入、完成、失败。2026 年 6 月的一项分析[13]指出，MCP（Model Context Protocol，模型上下文协议）、A2A 和 ACP（Agent Communication Protocol，Agent 通信协议）都不能表达治理语义：谁能授权什么、责任如何追溯，协议里没有位置。

两种位置的差别在可见性和出错时的处理：状态在 Agent 内部（窗口内），只有它自己看得见，出错也只有自己能发现，而它通常发现不了；状态在 Agent 外部（账本、文件、黑板），其他 Agent 与人可读、可审计，出错时可检查、可回滚。

![image](https://pbs.twimg.com/media/HSfF8hFagAA2_UW.jpg)

原则二：写权限与终止条件收敛

多 Agent 的并行只发生在"读"和"贡献智能"上，写操作必须保持单线程。Cognition 两篇文章[11]的共同点正是写权限收敛到一处。终止条件写成规则、由中心节点或人判断，是本文从五种范式对照中得出的判断。

。。。

## 人在哪一层

上面的证据把决策权和验证推向一个中心节点，现阶段这个节点是人。上海交大、清华等机构 2026 年 9 月的递归自我改进综述 [[14]](https://arxiv.org/abs/2609.11873) 把"AI 将经验沉淀为记忆和技能"的阶段定义为第四级，并写明目标设定、访问边界、受保护的评估和关键发布的权限仍由外部治理。对应本文的四个变量，决策权和失败可见性两项，现阶段由人持有终审，Agent 之间的互审作为第一道过滤。这个安排有时效性：Agent 能可靠审查自己的记忆之后，它应当改。

| 治理项                   | 现阶段归属                |
| --------------------- | -------------------- |
| 目标设定、访问边界、受保护的评估、关键发布 | 外部治理（人）              |
| 决策权（下一步由谁定）           | 人持终审，Agent 互审作为第一道过滤 |
| 失败可见性（出错谁先看见）         | 人持终审，Agent 互审作为第一道过滤 |

![image](https://pbs.twimg.com/media/HSfGAeBaEAA91Qn.jpg)

## 结论：一张判断表

选范式之前先思考四个问题。

| 问题                 | 怎么选                                                 |
| ------------------ | --------------------------------------------------- |
| **任务能否并行拆分**       | 能，用中心化的主管与工人或流水线；不能，单 Agent 往往更好，顺序任务上多 Agent 只会退化。 |
| **产物是一个答案还是一串交付物** | 一个答案，用辩论或黑板；一串交付物，用流水线或账本驱动的主管模式。                   |
| **状态放在哪**          | 无论选哪种，放在 Agent 之外，要能被其他 Agent 和人读到、检查，出错时能回滚。       |
| **写权限和终止条件归谁**     | 写权限收敛到一处，终止条件写成规则，终审留给人。                            |

![image](https://pbs.twimg.com/media/HSfHI4qaYAAHb-3.jpg)

多 Agent 协作是一组关于状态和决策权、失败和终止的结构选择，每一项都有文献可查，每一项也都能在自己的系统上被证伪。
