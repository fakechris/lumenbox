# Jev 101: what it is, and what you can build with it

I have read 10+ articles, watched 5 hours of content to understand what actually Jev is and then chose to write this. 

It is not a chatbot, It’s a whole new kind of AI, more like a classifier which takes an input and sends back an Output in 3 formats, no long paragraphs, 40-100X faster than existing model ( ChatGPT, Claude etc. ) 

$42 Per Billion input tokens. 238x Lower input price than Claude Fable 5.1

So it is cheaper yet faster on the same timeline enabling you to build your own AI products at scale. 

But Jev is not like old LLMs of chatbots where you give instruction and it returns you output in the form of paragraphs, texts etc, instead It enables you to give itself (Jev) naked inputs and then ask your question to Jev and then choose between 3 formats in which you want your answer. 

![image](https://pbs.twimg.com/media/HSljpIobwAAs53P.jpg)

## The three formats.

This is the whole surface area you need to Know. 

1. Choice: picks one option from a list you define. Up to 255 of them. Good for routing and categories.

2. Score: places the input on a scale you define. Good for urgency, quality, risk.

3. Noul: answers yes or no, as a number between 0 and 1.

Every answer comes back with probabilities and a confidence score attached. Typed. No JSON prompting, no parser, no retry loop when the model decides to wrap your object in a markdown fence.

![image](https://pbs.twimg.com/media/HSljpIObsAAITCo.jpg)

Here’s what a call actually looks like. This is an invoice dispute landing in a support inbox:

```python
from typesafe_sdk import Choice, Noul, Score, TypeSafeClient

client = TypeSafeClient()

response = client.system_one(
    state="I was charged twice for October. Same invoice number, two debits. Fix this today.",
    questions={
        "route": Choice(
            instructions="Which team handles this",
            criteria={
                "billing": "Charges, refunds, invoices",
                "technical": "Integration or API failures",
                "sales": "Pricing and plan questions",
            },
        ),
        "severity": Score(
            instructions="How badly this is hurting the customer",
            criteria=["Minor annoyance", "Blocking their work", "Losing them money"],
        ),
        "needs_human": Noul(
            instructions="This requires a person, not an automated reply",
        ),
    },
)
```

Three questions, one call. Questions in a single call evaluate in parallel, so twenty of them cost roughly what one costs. Ask everything you want to know about a piece of state at once. Designing around one question per call is the first mistake everyone makes.

## So name is the thesis!

The class name, System One, is the Kahneman reference: fast and intuitive, against the slow deliberate System 2 that every reasoning model lives in. The model’s own name isn’t. Jev comes from William Stanley Jevons, a 19th-century economist.

Jevons paradox: make a resource dramatically cheaper and people don’t save money, they consume far more of it.

That’s a thesis, not a pun. The bet isn’t that you’ll run your current AI workload cheaper. It’s that at this price you’ll start making judgment calls you’d never have paid a frontier model to make: per chunk, per row, per keystroke, per frame.

![image](https://pbs.twimg.com/media/HSljpILbMAEGgMO.jpg)

## The numbers, honestly.

![image](https://pbs.twimg.com/media/HSlmTKRbwAAX8hK.jpg)

Read the baseline before you quote the multiple. [The 193.6x figure](https://vercel.com/changelog/typesafe-ai-jev-now-available-on-ai-gateway), which Vercel repeats in its own changelog, comes from TypeSafe’s workflow evals against a mid-tier model, not a frontier one

So 7x when it’s one decision inside a bigger loop, 25x on a fair like-for-like, 200x when the vendor picks the workload. All three are true. Which one you get depends on what fraction of your latency was ever the decision.

On accuracy, Mike Taylor @hammer_mt  ran the cleanest test anyone has published. Jev caught six of seven planted defects. The frontier model caught all seven, and took 25 times longer to do it. On TypeSafe’s own four-workflow benchmark, Jev scores [67.8%](https://www.datacamp.com/blog/system-one-models-jev), level with GPT-5.6 Terra and a few points behind Sol and Opus 5.

And input runs $0.042 per million tokens, which is the $42-per-billion figure in my opener. [Vercel’s gateway lists it a shade under that](https://vercel.com/ai-gateway/models/jev), at about $0.04.

## Output tokens are free.

The speed number gets the headlines, but free output is what changes your architecture. Anything you run per-row or per-chunk was priced out before. One LLM call per retrieved chunk is not something anyone could afford at retrieval time. Now a per-chunk verdict costs less than the embedding lookup that produced the chunk. Michael Lee logged about 5,000 requests across classification, routing, intent and steering, and paid roughly two dollars.

## The confidence score is the actual product

A classifier hands you a label. You then have to decide whether to trust it, and you have nothing to decide with.

Jev hands you a label and a calibrated number saying how sure it is. The docs tell you to treat anything under 0.3 to 0.5 as a signal to stop and ask a human instead of acting.

That’s the difference between a fast classifier and a decision layer. The label tells you what it thinks. The confidence tells you whether you’re allowed to act on it. Without it you’re back to hoping.

## Feed it candidates. Don’t ask it to invent.

Every implementation that impressed anyone follows the same shape. Build the option set in code, then let Jev pick from it.

> A browser agent builds its action space from the DOM each step, and Jev chooses the next click.

> A retriever fetches chunks as normal, and Jev deletes the ones that don’t belong.

> A launcher ranks files, and Jev re-ranks them on every keystroke.

## What people are actually shipping

I’m not going to list everything; plenty of roundups already do that. These four patterns are worth stealing because each one generalises.

## 1. Model routing

Put Jev in front of your model fleet and let it decide which brain handles each request. 

It’s the most-cited job in the whole ecosystem, for a reason: the routing decision was always the cheapest part of the request, and it always got made by the most expensive thing in the stack. 

Sydney Runkle at LangChain [shipped this as middleware](https://www.langchain.com/blog/building-a-harness-with-jev). 

pip install langchain-typesafe, set TYPESAFE_API_KEY, and it’s a ModelRouterMiddleware with named choices and selection criteria. The probabilities stay in agent state, so you can audit why a request went where it went.

## 2. Context compaction

Coding agents hit the context ceiling and run a summarization prompt. Replace that with a Jev pass that scores every tool call for relevance and drops the dead weight. 

Tamara Tran shipped the idea, Alex Volkov ran it as a Claude plugin and took a session from nearly a million tokens down to 86K in about a second. 

Diogo Almeida’s own reaction was that this frees coding agents from designing around the KV cache. 

If that holds, the context window stops being the constraint you architect around. The plugin is at [github.com/tamaratran/fast-jev-compaction](https://github.com/tamaratran/fast-jev-compaction).

## 3. Safety review before execution

Every coding harness runs a classifier asking “should this command actually execute?” before auto mode lets it. Guillermo Rauch’s team benchmarked Jev against their current reviewer in fx and reported it up to 18x faster at p95, and more accurate. LangChain shipped an open version as AutoModeMiddleware the next day.

## 4. Real-time loops

Gregor Zunic’s [browser agent](https://github.com/browser-use/jev-ultrafast) is the one to clone first if you want to feel it. New action space every step, DOM as the state, small LLM only waking up when something needs typing. Zürich to London on Google Flights in [7.073 seconds at 1x speed](https://github.com/browser-use/jev-ultrafast/blob/main/docs/performance.md), for $0.0039. The repo publishes its methodology, which is more than most of these demos do.

## The Marketing of Jev gets wrong here

Jev Can’t hallucinate, this has been doing a lot of work in the launch copy, and it isn’t right.

Jev cannot emit an invalid type. That’s real, and it’s why the output drops straight into your code with no validation layer. But it can emit a wrong value that happens to be a valid one. Type safety is not correctness.

On [the Hacker News launch thread](https://news.ycombinator.com/item?id=49717558), a commenter laid out that this is fundamentally a classification model rather than an LLM. Diogo Almeida agreed, and only quibbled that he’d call it zero-shot rather than instruction-tuned. The same thread is where the type-safety-is-not-correctness objection got argued properly, and it’s worth reading before you repeat the marketing line.

So a very good zero-shot classifier with calibrated probabilities, behind a real API. Smaller than “a new kind of intelligence.” Still enough to change how you build.

The best description came from a builder [cataloguing what people were shipping](https://github.com/AnotiaWang/awesome-jev): an “AI if statement”. Three words, more useful than the launch video.

It’s the wrong tool when you need to see the reasoning, or when the set of valid answers isn’t knowable in advance. And if 67.8% agreement with a reference answer would count as a failure for you rather than a tradeoff, keep it out of the path.

Mike Taylor’s verdict on using it as a defect checker: an early-warning system, worth having because the honest alternative was not checking at all. Run it where you were previously running nothing, and keep the careful pass where you already have one.

## Start in three moves

![image](https://pbs.twimg.com/media/HSlkm9bawAAoGm_.jpg)

> Get access. It’s already behind the gateways you use: [Vercel AI Gateway](https://vercel.com/ai-gateway/models/jev) within 48 hours of launch, Cloudflare AI Gateway and OpenRouter in beta the same week. Direct is POST <https://api.typesafe.ai/v1/systemone> with a bearer token.

> Find your queue. Something expensive and incoming: leads, tickets, emails, retrieved chunks, tool calls. Anywhere a human or an LLM is currently making a cheap judgment slowly.

> Test it on a hundred real rows. Ask every question you have in one call. Threshold on confidence. Escalate anything under 0.5. One test run costs a fraction of a cent.

Then spend your actual effort on the grading. The option set and the question wording are the entire job. One builder who spent a week trying to break the model concluded that if the grading is wrong, nothing else matters. The API call is trivial. The taxonomy is the work.

Keep the big model for the hard thinking and the writing. Put Jev on every cheap judgment in between.
