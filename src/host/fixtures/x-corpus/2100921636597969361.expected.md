# Jev 在金融投资场景中的能力及应用实践

读财报时，有一种错不太容易发现：数字抄对了，却把“预计收入”写成了“已实现收入”。后面的分析再认真，也可能是在一个错误的前提上往下推。

昨天走红的 Jev，让我想到的就是这类检查。它能不能帮忙多看一遍，把这些容易漏掉的地方找出来？

我们围绕金融研究和 Agent 流程做了几千次真实API调用，按返回用量和官方单价估算，模型费用约0.05美元。这个价格太 fancy 了，效果也非常好。我想知道，它能不能接下一些投资场景里对效率和准确性要求比较高的活儿。

## 我自己先趴了一遍推特里比较热的Jev再金融领域应用的帖子，很酷，收藏一下：

[Jarrod Watts 做了一个交易机器人](https://x.com/jarrodwatts/status/2100356151468585346)：把价格数据交给 Jev，让它选买或卖，再连接链上订单簿。9月18日查看时，原帖约有87.5万次浏览。演示很直观，但帖中的300毫秒指区块节奏，不能当成模型每次判断的耗时，更不能据此判断策略赚钱。

[Brendan Playford 的做法更值得拆解](https://x.com/BrendanPlayford/status/2100485748533440990)。他用另一个模型预测价格路径，再把预测特征、市场数据、技术指标和新闻交给 Jev 判断行动。Jev 用的是其他模型和工具给它的结果，并没有独自包办整套分析。作者披露了早期模拟交易结果，我们没有复跑，收益也无法单独归功于 Jev。

我更想先试的是 [Rahil 的公告筛选实验](https://x.com/Anot/status/2100425243269468583)：从 SEC 文件里找回购、内部人交易和季度变化，为关注列表生成信息流。对每天读材料的人来说，这个实验的效果比较容易看出来。重要公告漏没漏，无关材料有没有少读几篇，都可以拿自己的关注列表试。

[flowp 的期货短线实验](https://x.com/theflowp_/status/2100858233996898404)则给热情泼了点冷水。每30秒，把纳斯达克、黄金和比特币期货的价格与技术指标交给 Jev，让它选择做多、做空、退出、调整止损或不操作。作者报告平均判断耗时611毫秒，却把项目戏称为“亏损竞技场”：一扣手续费，交易表现就值得重新看了。模型调用便宜，频繁交易的成本可不一定低。

[t0xhoodX Terminal 用它做代币风险筛查](https://x.com/t0xhoodX/status/2100872230993609071)。按作者介绍，程序先收集重复发币、持有人过少、缺少流动性等信号，再交给 Jev 判断看多、谨慎还是回避。权限和资金执行仍由程序控制。我觉得这个分工值得参考：先把证据找齐，再让模型判断，而不是让模型凭空评价一个代币。目前看到的是产品介绍，还没有独立效果评测。

[Galeon 的接入方案](https://x.com/HelloGaleon/status/2100846309813198990)也很具体：在原有交易系统里，让 Jev 判断多空方向、是否参与、风险等级，以及退出还是继续持有。结果还要经过策略检查和风控，不能凭一个模型概率直接下单。这回答了一个实际问题：已有交易系统，可以在哪一步用上 Jev？不过作者还没公布接入前后的对照结果，暂时只能参考它的设计。

## 所以 Jev 到底能帮你做什么？

Jev 不生成完整研报。你给它材料和问题，它返回选择、判断概率或评分。比如：这段话是在陈述业绩、提供未来指引，还是信息不足？结果可以直接被程序读取。[官方说明](https://docs.typesafe.ai/concepts/system-one)

看完这些例子，我想到几个平时就会遇到的问题。

电话会里的问句，很容易被写成结论。电话会上，分析师问“客户取消订单是不是变多了”，管理层回答“没有，保持稳定”。报告如果写成“公司确认取消订单增加”，引用虽然找得到，意思却反了。我们的短样本里，Jev 能分清提问和管理层陈述，也能区分未来收入预期与已实现业绩。

还有一种情况，计算本身没错，选的数据不对。用户要比较两个完整年度，拿到的却是全年与单季数据；用户要看全部资产风险，分析却漏掉了现金。我们测试过这两种情况，Jev 都识别出了冲突。数值继续让程序计算；已经能用字段规则检查的问题，也没必要多叫一次模型。

做持续跟踪时，重复消息也挺烦。“工厂继续停产”和“仍未恢复运营”可能只是同一条消息的改写，“公司宣布复产”才是新进展。我们的样本中，Jev 分清了这两种情况。但它也犯过错：新闻正文没给事件日期，它仍判成新事件。所以日期得另外核实，不能因为模型说“新”就发提醒。

交易环节也可以做类似检查。用户说“先研究，别下单”，拟议动作却是提交买单；接口超时，系统就打算认定失败并重下一笔。在这两条离线测试里，Jev 发现了下单与用户要求冲突，也没有把超时直接当成交易失败。权限、订单状态和防重复下单，仍要由交易系统负责。

## 怎么和主模型配合？

假设你的研究助手已经用一个主模型读材料、写报告。接 Jev 时，可以保留这个主模型，只增加一个检查步骤：

主模型写结论 → 程序取出结论和相关原文 → Jev 核验 → 有疑点再交回主模型处理。

例如，原文是“预计下季度收入8亿元”，报告却写成“本季度收入已达8亿元”。程序把这两句话及必要上下文交给 Jev，要求它从“支持、冲突、证据不足”里选。主模型收到疑点后补查或修改，Jev 不必重读整场会话。

不过，接进去以后会不会更费钱？缓存会不会受影响？这两个问题也得算。不同模型不能指望共享内部上下文缓存，但单独调用 Jev，并不意味着主模型原有缓存就被清空。保留同一主模型、保持历史前缀稳定，把核验结果追加到后面，才有机会继续利用缓存；实际命中还取决于供应商规则和有效期。[缓存机制参考](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

如果每查一句话，都要把整份财报重新发一遍，再让主模型重写全文，流程很可能更慢、更贵。Jev 单次便宜，不代表组合起来一定省钱。

## 拿你手边的一份报告试一下

如果想自己试，我建议先找一份熟悉的报告，挑十条能找到原文的结论。这样模型判断得对不对，你心里有数。

打开 [TypeSafe Playground](https://console.typesafe.ai/)，把一条结论和对应原文放进 state；原文保留章节标题、统计期间和相关上下文。然后添加一个 Choice 问题：

“只根据所给原文，判断它与待核验结论的关系。不要补充外部事实。”

选项可以这样写： 支持：原文明确支持结论。 冲突：结论与原文含义矛盾。 证据不足：现有材料无法确认。

先保留正确结论，再人为改错一个地方，例如把“预计”换成“已实现”，或把“单季”换成“全年”；最后删掉关键上下文。看看它能否识别错误，也能否在缺材料时保留“未知”。有时完整材料给它没问题，少一句关键说明就会出错，这种情况值得留意。

试的时候顺手记一下：哪些错误没发现，哪些正确结论被误报了，自己又花了多少时间复核。费用也一起记。先在后台对照，不直接据此改报告或屏蔽提醒。开发者可以沿着 [官方引用核验教程](https://docs.typesafe.ai/cookbooks/citation_check) 接入；注意教程带缓存，重放示例结果不算新的API实测。

## 现在值得接入吗？

如果是我，会先选公告筛选或引用检查中的一个来试。每天都要做，也能回头查原文，做得好不好比较容易判断。

我们的主评测集有104个不同输入，99条符合预设，5条不一致。这些是合成材料，预设由AI设计并交叉审阅，其中还包含失败后的诊断样本，不能当成生产准确率，也没有证明它优于其他模型。全部157次调用还包含重复测试和诊断。[测试记录与方法](https://xueqiu.feishu.cn/docx/BgXvdVmHNoEb62xzWSpceo4cnuf)

费用按官方每百万输入tokens 0.042美元估算，未与账单核对。104例短样本的本地完整响应，中位数1.22秒、P95为2.41秒。这个速度可以拿来试研究辅助，不能套用成交易执行承诺。[官方定价](https://docs.typesafe.ai/models)

接下来还是得拿同一批材料，和现在的办法比一遍。它多找出几个错，却让人多复核半天，也未必划算。要是原来的规则或主模型已经做得不错，我会先留着原方案。
