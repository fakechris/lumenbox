# Rides

Request a car on Uber, Lyft, Bolt, Grab or whatever operates where they are. A driver gets dispatched, so the person chooses the option and approves the request. You are done when they can find their car from your reply.

## Kinds of request

- Destination only ("Uber to SFO"): pickup is where they are.
- Both ends and a time ("office to 500 Howard at 6").
- Service only ("get me a Lyft"): the destination comes first.
- A future time ("tomorrow 7am to the airport"): a scheduled ride, not one now.

## Settle first

- Pickup: what they said, then home or work from `Recall`, then ask. State the exact pickup spot before requesting; a wrong pin sends the driver elsewhere.
- Destination the same way; saved places beat retyped addresses.
- Now or scheduled: "first thing tomorrow" or "at 6" is scheduled, never immediate. If the time is missing, ask; state weekday, date and time in their zone before entering it.
- `Recall` their usual service, ride type, and which payment they use for work versus personal.
- Use a connector if one is listed; otherwise the web app: `m.uber.com`, `ride.lyft.com`, or the service's own site. Web apps can lack ride types, scheduling windows and promotions the phone app has; say so when something expected is missing.

## Steps

1. Enter pickup and destination and stop at the ride-options screen.
2. List every option with its name, fare and how soon it can pick up. When the screen shows surge or peak pricing, point it out with the multiplier or the difference, and offer waiting as a choice.
3. Ask with `AskUser`, the options being the ride types on screen with prices. Never request the first one yourself.
4. Payment: a method saved on the account; if several, ask which (fold it into the same question when short). None saved: `HandOverDesktop` for them to add one. A fare can end above the quote, so do not plan around a fixed amount.
5. Request the ride, or schedule it for the confirmed time. Any payment confirmation the site raises is theirs.
6. After matching, capture driver name, car make, model and colour, plate, pickup ETA, and the PIN if shown.
7. Scheduled ride: report the window and that driver details arrive nearer pickup.

## Presenting

- Only the ride types, prices and ETAs the screen shows; never estimate.
- Cheapest and fastest first when they differ, with what the extra money buys (bigger car, nicer car, shorter wait).
- Surge belongs beside the option, not in a footnote.

## The confirmation (required)

Each on its own line, exactly as shown: driver name; car make, model and colour; plate; ETA; PIN when there is one. "Lyft booked, $19" alone leaves them hunting for the car. If a detail has not appeared yet, say so and look again before the ETA runs out. Also give pickup spot, destination, fare shown at request, and the payment method. Airport pickups: include the zone or terminal the app names.

## Watch for

- Surge moves between looking and requesting; if the request screen shows more, ask again.
- Several payment methods are a real choice; a business profile changes who pays.
- Do not save the ride itself to memory; only a stated service or payment preference.
